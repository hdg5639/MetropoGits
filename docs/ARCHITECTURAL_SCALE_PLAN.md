# Architectural scale and campus estates

Maintainer request, 2026-10-21: stop adding catalog names. Prioritize spatial
requirements -> variable facility sites -> source-linked complexes -> campus
composition -> silhouette. Tiny per-file recipe details cannot solve scale.

## Audit, not blanket agreement

- planning.slots still reserves8x8 frontage addresses; populate keeps each City
  building's original width/depth. Normalized architecture fits that envelope.
- The116-member limit belongs to the older courtyard pilot. Programmed/fabric
  campus paths already reserve a whole neighborhood (12–256 sources), connected
  courts/promenades and perimeter access before assignment. Do not remove them.
- Existing source-affinity landmarks are persistent, reversible groups. However
  they are fitted AFTER individual addresses are assigned, and small-group
  reservations/perimeter roads often prevent meaningful larger complexes.
-85 names are not85 unique silhouettes or85 recognized technologies. Report
  actual selections and neutral fallbacks, not catalog size as visual progress.

## Delivery sequence

1. **Dedicated compound sites before file subdivision** (current vertical slice).
   Introduce an opt-in campus estate planner. Build bounded source-affinity
   groups first; calculate the land required by each real group; fit variable
   rectangular facility sites beside the shared pedestrian system; only then
   assign constituent source addresses inside each site. Preserve the existing
   file representation as the inspector/explicit-expansion layer, not the
   mandatory visible architecture unit. Never group solely by role colour.
2. **Individual program-sized footprints**. Generalize physical width/depth and
   capacity requests beyond source-address units, including noncampus streets.
   Define the derived physical-envelope contract and its independent
   reconstruction before changing the current World/source-size invariant.
   Do not silently reinterpret original City dimensions or weaken validators.
3. **District-scale campus composition**. Increase estate variety, improve
   multiple connected quadrangles/spines and perimeter vehicle access without
   copying one radial emblem. Nature remains first; do not bulldoze terrain.
4. **Silhouette audit**. Measure actual recipe/massing distribution and neutral
   fallback frequency, distinguish major physical families in grayscale, and
   tune proportions on their new land capacity. Do not add names as a proxy.

## Estate acceptance

- Planned site area/shape varies with actual group membership; source and
  shared-local-target affinity is disclosed, never a new peer dependency.
- Larger dedicated sites hold interconnected visible complexes and shared open
  space. Public walking paths remain outside building envelopes; original
  source doors and exact source trips are retained for drill-down/Synthetic.
- Source IDs/roles/evidence and original UCG/City contracts stay unchanged.
  No automatic zoom explosion into dozens of small buildings.
- Terrain/court/street/parcel clearance, capacity, external-road connectivity,
  canonical determinism, nearby-edit stability and bounded work are checked.
- Compare GJ, OJ, PocketBase and SQLiteBrowser overview/district/close renders,
  report selected sites, selected complexes, rejected/fallback reasons, actual
  archetype distribution and geometry cost. Include unknown input.
- A safe fallback is necessary, but four fallback outputs do not demonstrate a
  successful new planner. Require real positive source-backed corpus output.

This is a staged implementation, not a claim that the entire redesign is done.
Progress and actual renders belong in QUALITY_LOG. Existing default layouts
remain available for compatibility and comparison.
