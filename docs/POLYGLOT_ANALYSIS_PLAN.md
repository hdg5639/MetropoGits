# Polyglot analysis and evidence-backed facilities

2026-10-20. User-authorized broad language/framework/library expansion and
corresponding building facilities. This is not a promise to implement every
language compiler, infer dynamic dispatch or classify every file semantically.

## Baseline

Java already extracts plain-Java imports, declarations, inheritance and lexical
type references; Spring is its deepest framework layer, not its only parser.
JS/TS already extracts static ESM/CommonJS imports and configured aliases.
Neither is a full JavaParser/TypeScript compiler binding engine. Other source
languages currently fall back to structural buildings; Vue/Svelte lack imports.

## Delivery slices

1. Shared bounded evidence writer and Python stdlib AST adapter: local modules,
   relative imports, explicit external imports, class inheritance, declaration
   details and import-bound calls/decorators. Never import/execute the target.
2. Bounded lexical structural adapters for Go, Rust, C/C++, C#, Kotlin, Scala,
   PHP, Ruby, Swift, Dart and Lua where explicit module syntax can be proved.
   Vue/Svelte script sections reuse the JS/TS tokenizer. State lexical versus
   AST coverage explicitly; do not relabel token matching as compiler resolution.
3. Versioned declarative framework signatures across JVM, Python, Node/UI,
   Go/Rust, .NET and other supported ecosystems. Imported identity + actual
   call/decorator/inheritance/attribute usage produces roles; declarations alone
   produce technology/dependency facts, never a deployed DB or remote service.
4. Distinct facility silhouettes for evidenced API/UI/CLI/test/data/auth/worker
   and storage roles, in the existing extensible scene archetype namespace.
   CPU and WebGL forms must agree, fit original envelopes and rotate together.
5. Real cross-repository builds and viewer inspection, deterministic repeats,
   adversarial/lookalike fixtures and a published support/limitations matrix.

## Contracts and guardrails

- Keep UCG/City schemas and stable path-based IDs; all added facts have exact
  source paths/lines, declared extractor versions and confidence classes.
- Local ambiguous or missing modules stay unresolved with diagnostics. No
  basename guessing across repositories/modules. No fake CALLS/HTTP/topic edges.
- Comments, strings, templates, shadowed/reassigned imported names and local
  lookalikes must not produce direct framework roles. Reject constructs outside
  an adapter's supported subset rather than manufacturing exact bindings.
- No target builds, package installs, eval/exec/import, new runtime AI/cloud,
  parser auto-download or mandatory external language toolchains.
- Respect scanner byte/path limits plus parser token/node/work budgets. Static
  manifests never expose raw credentials, dependency URLs or source text.
- Immutable existing catalog releases and golden source IDs are retained.
  New catalog release/version is recorded; existing snapshots are not blindly
  rewritten to hide changed source evidence.
- Each completed slice gets tests, a real pipeline checkpoint and an atomic
  commit. Keep the already-merged main stable; work on feat/polyglot-analysis.

## Acceptance

Use existing GJ/OJ plus cloned FastAPI RealWorld, Svelte RealWorld, PocketBase,
bat/Ratatui and SQLiteBrowser as applicable. Report per-language parsed files,
local/external/unresolved edges, evidence-backed roles, remaining generics,
generation time and actual inspected artifact paths. Generic is not failure.
Framework support is the tested signature subset, not whole-framework coverage.
Preserve source facts through streets/World rendering and Synthetic paths.

Prefer a broad working vertical slice over weeks of one-parser micro-polish;
fix false evidence/security defects before adding another framework label.
