# 도로 중심 블록과 필지의 통합 및 분할 계획

합의일: 2026-10-18. 목표는 Cities: Skylines를 연상시키는 읽기 쉬운 도시 공간이다.
게임의 에셋이나 교통 시뮬레이션을 복제하는 것이 아니라, 서비스 구역 안에 도로와
블록이 있고 그 도로를 향해 건물과 복합 시설이 놓이는 구조를 만든다.

기준은 **서비스 구역 → 도로로 나뉜 블록 → 필지와 복합 시설**이다. 디렉터리
소유권과 원본 파일은 보존한다. 도시 전체를 직사각형으로 강제하지 않되 내부에는
식별할 수 있는 블록을 둔다. 이 문서의 목표 구조는 아직 구현 완료가 아니다.

## 통합 기준

- 같은 서비스 구역 안의 근접한 파일을 대상으로 한다. 역할이 같거나 실제 관계가
  밀접해야 하며, 역할 일치는 검증된 근거를 사용한다.
- 도로를 가로지르거나 다른 파일을 덮는 통합, 먼 파일을 개수만으로 묶는 통합은 금지한다.
- 통합 결과는 거대한 단일 박스보다 본관과 부속 동이 있는 복합 시설로 표현한다.
  각 동은 구성 파일의 시각 집계이지 새 코드 요소나 서비스가 아니다.
- 게이트와 테스트 시설은 확대해도 자동 해체하지 않는다. 구성 파일은 Inspector에서
  전부 추적하고 사용자가 명시적으로 펼친 경우에만 원래 건물을 드러낸다.

## 분할과 배치 기준

길거나 큰 블록은 실제 관계가 드나드는 방향과 접근성을 평가하여 나눈다. 관계 없는
빈 공간을 채우려고 도로를 만들지 않는다. 건물군 내부의 짧은 진입로, 블록 사이의
공유 도로, 서비스 간 간선을 구별한다. 건물은 블록 한쪽 구석이 아니라 도로에 접한
필지에 배치한다. 모든 틈을 같은 폭으로 벌리는 방식은 사용하지 않는다.

관계 수요와 거리 공간을 함께 계획하되, 원본 디렉터리 경계 밖으로 파일을 옮기지
않는다. 역할만으로 외부 통신이나 실제 요청 흐름을 추정하지 않는다. 근거가 적은
입력은 구조적 블록으로 남기고 존재하지 않는 관계를 보충하지 않는다.

## 도로의 통합과 분기

가까운 평행 경로는 건물 관통과 과도한 우회가 없는 경우 공용 회랑으로 모으고
목적지 가까이에서 짧게 갈라지도록 한다. 공유 노면과 교차로는 연속된 공간으로 읽혀야
한다. 모든 세그먼트에 테두리와 중앙선을 반복해서 배선처럼 보이게 하지 않는다.

A→B와 C→D가 같은 도로를 사용해도 A→D가 생긴 것은 아니다. 구간별 경로 ID와
원본 edge ID를 보존한다. 선택·Inspector·Synthetic은 같은 경로를 사용하며 교차로에서
임의로 갈라지지 않는다. 기본 화면은 도시를, 선택 화면은 정확한 관계를 우선한다.
곡선이나 장식만 추가해서 잘못된 블록 구조를 숨기지 않는다.

## 구현 단계

1. **공유 도로의 연속성 기반:** 현재 좌표를 고정하고 꺾임·총 경로 길이·공유 구간·
   근접 평행 구간을 측정한다. 방향을 고려한 결정론적 경로 탐색으로 불필요한 꺾임을
   줄이는지 검증한다. 기존 우회 상한과 안전 한도를 유지한다. 이 단계만으로 블록
   재배치나 평행 회랑 통합이 완성되었다고 부르지 않는다.
2. **한 구역의 블록과 필지 실험:** 동일한 규칙으로 GJ-Cloud와 GamjaOJ의 구역을
   선택하여 도로 수요·블록 크기·건물 전면 배치를 함께 비교한다. 프로젝트 이름을
   하드코딩하지 않는다. 현재 도시와 후보를 함께 보존한다.
3. **복합 시설과 연속 노면:** 도로를 침범하지 않는 다동 시설과 교차로 표현을
   적용한다. WebGL과 SVG가 같은 배치·구성원·경로를 사용해야 한다.
4. **확장 결정:** 두 저장소 및 작은 구조 전용 fixture에서 개선을 확인한 뒤 확대한다.
   실패한 후보는 기본값으로 승격하지 않는다.

첫 단계는 [ADR-016](adr/ADR-016.md)의 파생 경로 변경 범위다. 정식 블록 재배치는
레이아웃 버전, 이전 scene hint 처리, 소비자 호환성 및 변경 허용 범위를 별도 ADR로
확정한 뒤 적용한다. 이 계획을 UCG/City 스키마나 안정 ID의 무제한 변경 승인으로
해석하지 않는다.

## 검증과 완료 기준

- 원본 관계 집합·confidence·evidence·파일 소유권을 보존한다.
- 경로·노면의 건물 관통은 0이며 우회 제한을 지킨다.
- 같은 입력을 반복하거나 배열 순서를 바꿔도 결과가 같다.
- 건물 이동, 총 도시 면적, 밀도와 공백, 도로 길이·꺾임·공유율을 전후 비교한다.
  전체 알고리즘 교체 시 이동과 이후 작은 수정에 따른 이동을 따로 보고한다.
- 같은 카메라·LOD에서 GJ-Cloud, GamjaOJ를 실제 WebGL과 SVG로 확인한다.
  도로가 줄었다는 수치만으로 시각 개선을 선언하지 않는다.
- Synthetic의 정적 geometry 재생성 0회를 유지하며 조작 CPU와 라우팅 자원을 측정한다.
- 수용 기준은 처음 보는 사람이 주요 구역, 블록, 공용 도로와 개별 접근로를 구별하고
  선택한 관계를 원본 파일까지 추적할 수 있는가이다.

## 유지할 후속 이슈

### 2단계 실험 경계

첫 필지 실험은 개발용 비교 보고서이며 기본 배치 알고리즘을 바꾸지 않는다.
`parcel-pilot/0.1` 보고서의 후보 좌표는 City Scene이 아니며 layout hint로 사용할 수 없다.
UCG와 입력 city.json은 읽기 전용으로 유지한다. 자식 구역이 없는 8~64개 파일 구역 중
실제 연결 파일 쌍이 가장 많은 구역을 선택한다(동률은 구역 ID). 같은 선택 규칙을 모든
저장소에 적용한다. 기존 polygon 안에서 두 줄의 필지 사이에 7-unit 접근 공간을 예약하고,
실제 관계의 이웃 위치를 기준으로 필지를 배정한다. 다섯 열마다 교차 접근 공간도 예약해
최대 2×5개 필지의 블록을 만든다. 거리만 최소화해 한쪽이 비지 않도록
블록의 수용량에 비례해 건물 수를 배분한다. 예약 공간은 관계가 아닌 빈 공간이며,
관계가 사용한 구간만 도로로 렌더링한다. 수용 공간이 부족하면 후보를 만들지 않는다.

보고서는 같은 축척의 기존/후보 평면 SVG, 전체 원본 관계 ID를 보존하는 파생 경로,
원본 파일별 이동량, 도로 길이/꺾임/관통 검사를 제공한다. 선택 구역 외 건물은 고정한다.
이는 한 leaf 구역의 접근성 실험이지 서비스 전체 재배치·복합 시설·WebGL 적용 완료가 아니다.
실험 좌표는 콜드 배치이며 파일 추가에 따른 구역 내부 이동은 아직 안정성을 보장하지 않는다.
정식 승격 전 별도 ADR, hint 호환성, 실제 WebGL 비교와 작은 변경 안정성 검증이 필요하다.

현재 Synthetic은 최대 96개 경로를 고정 간격으로 선택하므로 모든 도로에 이동체가
보이지 않는다. LOD에서 숨긴 구간의 이동체도 숨긴다. 도로와 이동 경로의 일치를
유지하면서 대표성 부족을 별도로 검토한다. 블록 작업에 교통량 시뮬레이션을 섞지 않는다.

## 첫 단계의 구현 결과

2026-10-18 방향 및 출발·도착 진입로를 고려한 `visual-access/0.2`를 적용했다.
GJ-Cloud와 GamjaOJ의 원본 그래프·건물 좌표·경로별 원본 관계 집합은 유지했다.
전체 블록 배치나 평행 회랑을 직접 합치는 알고리즘은 아직 적용하지 않았다.

| 지표 | GJ 이전 → 적용 | OJ 이전 → 적용 |
| --- | ---: | ---: |
| 경로 전체 꺾임 합계 | 31,198 → 24,516 | 8,901 → 7,915 |
| 노면 중심선 길이 | 52,345.5 → 51,796 | 12,936.5 → 12,376.5 |
| 근접 평행 구간 쌍의 겹치는 길이 | 31,850 → 31,206 | 7,826 → 6,916 |
| 탐색 상태 확장 횟수 | 1,325,361 → 2,384,938 | 242,764 → 449,967 |

길이는 월드 단위다. 평행 지표는 같은 종류·방향이고 7 단위 이내인 비진입로
구간 쌍의 겹치는 길이 합계다. 두 길 사이의 건물·경계를 고려한 통합 가능성이나
중복 도로의 증거는 아니며, 한 구간이 여러 쌍에 포함될 수 있다.
공유 길이는 경로 수로 가중하지 않은 노면 중심선 기준으로 별도 집계한다.

재현: `python -m scripts.road_metrics <기존 build 폴더> <새 build 폴더>`.
이는 렌더링 기하의 계측이며 실제 트래픽이나 분석 정확도 점수가 아니다.
큰 입력의 탐색 비용 증가를 후속 블록 실험에서도 반드시 비교한다.

## 한 구역 필지 실험 결과

개발용 실행: `python -m scripts.parcel_pilot <기존 build 폴더> --out <새 비교 폴더>`.
기존 출력 폴더 덮어쓰기를 거부한다. 결과는 `index.html`과 `report.json`이며
정식 `city.json`을 생성하지 않는다. 2026-10-18 로컬 검토 결과는
`artifacts/visual/parcel-pilot-r4/{gj,oj}/index.html`에 보존했다(공개 커밋 제외).

같은 규칙으로 GJ의 Ops `application/preview/analysis`(36개 파일), OJ의
`generation/service`(49개 파일)가 선택됐다. 비교 대상은 **해당 구역에 닿는 관계만**이며
도시 전체 수치가 아니다. 선택 구역 밖 건물은 전부 고정하고 라우팅 장애물로 유지했다.

| 지표 | GJ 기존 → 후보 | OJ 기존 → 후보 |
| --- | ---: | ---: |
| 파일 쌍 경로 / 원본 edge | 357 / 556 유지 | 528 / 893 유지 |
| 경로 길이 합 | 65,667 → 56,945 | 79,117 → 70,101 |
| 꺾임 합 | 2,113 → 1,893 | 2,937 → 2,717 |
| 노면 중심선 길이 | 5,938.5 → 4,885 | 5,382 → 5,193 |
| 근접 평행 쌍 길이 | 3,013.5 → 1,806 | 2,975 → 3,174.5 |

두 후보 모두 관계 누락, 노면/건물 관통, 건물 겹침, 소유 구역 이탈은 0이다.
GJ 35개, OJ 48개 건물이 실험 좌표에서 이동했다. 경계와 건물 크기는 고정했으므로
면적이나 전체 밀도 개선을 주장하지 않는다. 반복 생성한 보고서 바이트가 일치했다.

실제 Chrome SVG 비교에서는 도로 옆 필지와 교차 공간이 구분되지만, OJ의 평행 경로는
오히려 늘었고 GJ 상단 여백도 남았다. **실험 도구는 구현했으나 기본 배치 승격은 보류한다.**
후보의 WebGL/README showcase 및 Synthetic 성능은 미검증이다(기본 뷰어는 변경하지 않음).
다음 우선순위는 고정 블록 폭과 고정 구역 면적의 제약을 풀 방법을 ADR로 정리하고,
공유 간선 수요에 따라 블록 경계를 조정하면서 평행 도로·여백을 함께 줄이는 것이다.

### 후속 실험: 실제 경로로 후보 선택

정식 layout/scene은 바꾸지 않고 `parcel-pilot/0.2`에서 블록 폭과 교차 공간 위치를
달리한 후보를 비교한다. 기존과 같은 구역을 선택하고 소유 경계는 고정한다.
건물 간 맨해튼 거리만으로 최종 결정하지 않는다. 제한된 후보에 실제 라우터를 적용하고
원본 관계, 관통, 평행 경로, 경로 길이, 꺾임, 큰 빈 공간을 비교한다.
관계 손실이나 기하 위반은 탈락이며, 주요 계측이 기준보다 악화되면 채택하지 않는다.
모든 후보가 실패하면 원본을 유지한다. 후보별 선택/탈락 이유와 탐색 상한을 보고서에 남긴다.
빈 공간 지표는 polygon 내부에서 건물이 없는 최대 격자 직사각형 면적이며 도로 공간도
포함한다. 실제 공터의 의미나 토지 낭비율을 주장하지 않는다. City/hint 승격은 여전히 별도 결정이다.

구현 범위: 구역 선택은 0.1과 동일하게 유지한다. 선택 구역 안에서 3/4/5/7열 블록,
가로/세로 배치, 접근 공간 위상 3개, 교차 공간 위치 3개(처음/중간/끝)의 최대 72개
후보를 생성한다. 빈 직사각형 면적 → 관계 거리 → 이동량 → 고정 구성 순으로 정렬하고
좌표가 동일한 후보를 제거한 상위 6개만 실제 라우팅한다. baseline 포함 최대 7회,
각 라우터의 기존 5M 탐색 확장 한도를 유지한다. 전체 최적해 탐색이 아니다.

원본 입력 배치보다 경로 길이·꺾임·노면 중심선·평행 쌍 길이·빈 직사각형 면적이
하나라도 커지면 탈락한다. 안전 검사를 통과하고 하나 이상 개선된 후보 중 빈 직사각형,
평행 쌍 길이, 경로 길이, 꺾임, 이동량 순으로 선택한다. 모든 후보 실패 시
`BASELINE_RETAINED`와 탈락 사유를 보고한다. 이 판정은 원본 입력과의 비교이지,
이전 미승격 실험의 모든 지표보다 좋아진다는 주장이 아니다.

### 0.2 실제 검토 결과

`artifacts/visual/parcel-adaptive-r1/{gj,oj}/index.html`에서 원본/새 후보를 비교한다.
화면은 실제 경로 기하의 SVG이며 후보의 3D 렌더링은 아직 적용하지 않았다.

동일 카메라 WebGL 검토다. 기본값 승격은 별도이며, 작은 편집의 구역 내부 이동 안정성,
서비스 전체 도로 공유, Synthetic 비용 검증은 여전히 필요하다.

## Opt-in 3D 실험

ADR-017에 따라 선택된 한 구역을 실제 City/WebGL/SVG에 연결했다.
일반 `metropogits build`와 Action 기본값은 여전히 `hierarchical-paged/1.14`다.
새 enum `hierarchical-parcel/0.1-experimental`은 기존 `city/0.2` 필드를 사용한다.
구버전 enum validator는 업데이트가 필요하다. 기본 배치 승격이나 전 구역 최적화가 아니다.

```text
python -m scripts.parcel_viewer <검증된-1.14-build> --out <새-폴더>
python -m scripts.parcel_viewer <현재-1.14-build> --out <다른-새-폴더> --previous-scene <이전-실험-city.json>
```

- 입력 `graph.ucg.json`/`city.json`을 검증하고 후보를 직접 재계산한다.
  입력 HTML/JS는 실행하거나 복사하지 않는다. 번들 자산만 새로 출력한다.
- 안전한 후보가 없으면 `BASELINE_RETAINED`로 원본 좌표를 유지한다.
- 건물 ID/소유 구역/크기/역할/근거, 디렉터리 전체, network ID/edgeIds를 보존한다.
  변경 장애물 기준으로 canonical network.path와 **도시 전체** access route를 재계산한다.
  관계 누락·부분 라우팅·노면 관통은 출력 실패이며 완성된 결과로 게시하지 않는다.
- 같은 실험 버전의 hint만 받는다. 디렉터리 기하와 파일 목록/소유권/평면 크기가 같으면
  모든 X/Z를 고정하고 현재 역할·높이·관계를 반영한다. 구조 변경은 오류로 알리며
  사용자가 hint를 빼야 cold layout을 수행한다. 추가 파일의 증분 배치는 아직 미지원이다.
- `decision.json`은 후보 판단과 도시 전체 계측을 담는다. manifest는 기존 진단 상태와
  체크섬 형식을 유지하고 `options.experimental: true`로 실험 여부를 구분한다.
  뷰어 상단에도 EXPERIMENTAL PARCEL LAYOUT을 표시한다.
- 입력 각각 64 MiB, 건물 5,000개, 구역 10,000개, canonical 격자 추정 100,000셀을
  상한으로 둔다. 기본 access router의 탐색 한도는 늘리지 않는다.

2026-10-18 검토 출력(로컬 비공개 산출물, 커밋 제외):

- 실제 뷰어: `artifacts/visual/parcel-3d-r2/{gj,oj}/index.html`
- 동일 시점/거리/Detail 전후 비교: `artifacts/visual/parcel-3d-focus-r3/index.html`
- 상호작용·Synthetic 계측: `artifacts/visual/parcel-3d-audit-r3/index.html`

GJ 35개/OJ 49개 파일만 이동했으며 다른 구역 건물과 디렉터리는 고정했다.
도시 전체 GJ 4,209 경로/6,157 edge, OJ 1,381 경로/2,243 edge를 보존했고
관계 누락과 노면/건물 관통은 0이다. 같은 카메라에서 건물 열 사이의 도로 공간이
더 구분되지만, 직교 배선 느낌과 구역 외곽의 여백은 여전히 남는다. 전체 도시 윤곽,
고정된 구역 면적, 작은 README에서의 차이는 크게 바뀌지 않는다.
반복 생성과 hint 보존, 실제 WebGL 선택/카메라 이동/필터/Synthetic을 검증한다.
전체 도시 재라우팅은 움직이지 않은 구역의 도로 및 파생 집계 외형도 바꿀 수 있다.
단일 구역 pilot 계측의 개선을 전체 도시 지표 개선으로 일반화하면 안 된다.

도시 전체 재라우팅 계측(원본 → 실험):

여러 구역 간 도로 공유/블록 경계 조정 실험으로 진행한다. 전 구역 일괄 적용은 보류한다.

## 의존성 도로 통합 우선 작업

사용자의 확대 화면에서 굵은 길과 얇은 길 모두 실제 DEPENDENCY_ROAD임을 확인했다.
따라서 선 장식 정리보다 **인접 평행 도로 통합과 실제 관계 경로 재배정**을 우선한다.
ADR-018에 경로/도로망 평가 분리, 우회 한도와 단계별 구현 범위를 기록한다.

1. 건물/출입구를 고정하고, 기존 도로로 안전하게 우회 가능한 평행 구간을 찾는다.
2. 영향받는 관계를 모두 재배정할 수 있을 때만 통합하고, 미사용 도로는 제거한다.
   전체 노면 길이·평행 중복은 줄이고 개별 이동 거리는 기존 우회 한도 안에서 허용한다.
3. 이어서 가까운 접속점을 교차로로 모으고 연결된 노면을 만든다.
4. 충분한 공간과 여러 주요 접근로가 있는 곳에만 로터리를 검토한다.
   로터리 경로와 Synthetic도 함께 바꾼다. 원형 장식만 추가하지 않는다.

첫 작업은 1–2의 opt-in 도로망 후처리다. CLI 기본값과 필지 후보 평가는 유지한다.
관계 ID/출발·도착은 보존하고 새 의존성을 만들지 않는다. 중도 탐색 실패는 기존 경로를
유지하며, GJ/OJ 전체 도시와 실제 사용자 확대 구역의 전후 비교를 함께 확인한다.

교차로 노면 정리이며, 로터리는 충분한 공간이 확인된 후보에 한해 별도로 검증한다.

### 교차로 내부 선 정리

WebGL의 기존 교차점을 같은 종류의 접근 도로 노면으로 이어 붙였다. 도로 사각형들의
합집합 안쪽만 채워 내부 테두리 이음새를 덮고, 중앙선은 교차로 입구에서 끊는다.
짧은 두 교차로 사이에는 중앙선이 생략될 수 있지만 도로와 실제 관계는 유지된다.
선택 시 전체 관계 경로와 Synthetic의 이동 궤적은 바뀌지 않는다.

- 새 출력: `artifacts/visual/junction-surface-r1/{gj,oj}/index.html`
- 같은 카메라 확대 비교: `artifacts/visual/junction-surface-focus-r1/index.html`
- 상호작용·Synthetic 검증: `artifacts/visual/junction-surface-audit-r1/index.html`

감자박스 2,959개, 감자OJ 652개 Detail 교차점의 노면을 정리했다. 전후 UCG/City,
전체 관계 경로, 정적 preview/showcase SVG는 동일하며 노면 범위를 넓히지 않았다.
Canvas/SVG에는 원래 내부 테두리·중앙선을 겹쳐 그리는 처리가 없어 변경하지 않았다.
WebGL의 겹친 십자선·작은 사각형은 줄었지만, 도시 전체가 직교형이고 일부 접근로가
빽빽한 문제는 남는다. 가까운 교차점 자체를 합치는 작업과 실제 경로를 따르는 로터리는
아직 구현하지 않았다. 다음은 근접 교차점·짧은 분기를 묶는 후보를 기존 우회 한도,
노면 안전성, 관계 보존 기준으로 평가하는 작업이다.

### 가까운 교차점의 짧은 분기 통합

`python -m scripts.road_consolidation <기존 build> --out <새 폴더> --junctions`

살아 있는 교차로로 보낼 수 있을 때만 적용한다. 적어도 하나의 T자 분기가 사라져야
한다. 건물 진입점은 후보에서 제외하며, 원본 라우팅 기준 거리·꺾임 한도를 두 단계가
공유한다. 기존 우회에 다시 우회 허용량을 얹지 않는다. 연결점 강제 이동이나 신규
도로 개설이 아니며, 짧은 관계 때문에 과한 우회가 필요한 후보는 거절한다.

감자박스 확대 화면의 짧은 가로 분기가 줄었지만, 감자OJ의 선택 구역 차이는 작다.
전체 도시 배치·스카이라인은 바뀌지 않았고 직교 도로 느낌도 남아 있다. 다음에는
남은 복잡한 합류부를 대상으로 로터리/완만한 연결의 공간·경로 안전성을 검토한다.
장식 원을 추가하거나 우회 제한을 풀어서 통합률을 올리지는 않는다.

### 정량 등급과 간선 중심 계획

ADR-019에 사용자의 ‘과감한 통합·분할’을 정량 기준과 단계별 구현으로 기록했다.
관계 종류와 도로 등급을 분리하고, 중복 없는 엣지·출발/도착 파일·주요 구역 간
연결 수로 골목/일반 도로/대로/구역 간 간선 수요를 구분한다. 정적 의존성 수를
실제 교통량으로 부르거나 DEPENDENCY_ROAD를 HTTP_HIGHWAY로 바꾸지 않는다.

첫 단계는 기존 도로의 수치·등급·안전 폭 제한을 Inspector와 렌더러에 표시하는 것이다.
이어서 연속된 간선과 적은 진입점을 계획하고, 도로 공간을 먼저 예약하는 opt-in
