## 3. 이번에 바로 할 작업 — W-03/04/05/06 묶음

생성 순서:

`원본 서비스 소유권 → 근거 있는 동네 핵심+연관 파일 → 토지 배분 →
패턴과 독립적인 접근 간선/블록 절단 → 로컬 문법/필지 → 회전 건물 → 원본 관계 라우팅`

첫 세로 조각은 평지/볼록 커널 안에서 만든다. 의미 동네의 핵심 파일은 보존하고,
보조 멤버의 합류는 실제 edge ID로 설명한다. 역할을 새로 부여하지 않는다.
큰길/블록 경계를 먼저 계산하고, 기존 다섯 문법은 작은 로컬 공간에만 적용한다.
기존 모드의 의미/바이트를 조용히 바꾸지 않고 새로운 opt-in 버전으로 비교한다.
모든 Voronoi 경계를 도로로 칠하는 방식은 쓰지 않는다.

필수 회귀 검사:

- 역할 중심의 핵심 파일이 실제 동네 안에 있는가; 보조 멤버의 근거 edge는 유효한가.
- 패턴 변경과 건물 배치 전에도 주요 도로/블록이 존재하며, 로컬 패턴 변경으로
  주요 도로망 전체가 재생성되지 않는가.
- 블록은 실제 도로와 경계로 정의되는가. 완전한 도로 폐합이 아닌 외곽/행정 경계는
  그 사실을 명시하고, 단순 셀이나 AABB를 도로로 둘러싸인 블록이라고 속이지 않는가.
- 같은 입력의 바이트 일치, 실제 소규모 수정 힌트 안정성, 전체 건물·edge 보존,
  필지/건물/전폭 도로 충돌0, 전 입구 접근성을 확인했는가.
- GJ/OJ + unknown 코퍼스의 실제 Overview/District/Detail/CPU/Canvas를 보았는가.
- 실제 차이가 눈에 보이는가. 관계 거리/각도 엔트로피/테스트 수만으로 완료하지 않기.

## 4. 작업 순서와 중단 규칙

1. 이 누적 문서와 좁은 구현 결정 기록 → 별도 docs 커밋.
2. 동네 핵심/근거와 패턴 독립적 큰길·블록의 실동작 세로 조각 → 체크포인트/커밋.
3. 실제 결과에서 구조적 결함 우선 수정. 패턴 종류/곡선 미세조정에 매몰되지 않기.
4. 구조가 읽힐 때 W-15 재질 분리, 이후 LOD/아키타입/윤곽·지형 확장 순으로 재평가.

피드백이 오면 기존 W 항목을 삭제하지 않고 `유지/수정/대기/기각`을 갱신한다.
새 약속은 이 문서와 품질 로그에 남긴다. 미완료를 최종/완성/개선 성공으로 부르지 않는다.
저효율 미세 최적화가 반복되면 그 자리에서 전체 화면과 기준을 재확인한다.

## 5. 실행·전달 규칙

- 작업 단위마다 테스트 후 별도 conventional commit, 본문 bullet 필수.
- 기존 인간 Git identity 유지, 에이전트/봇/AI 기여자·co-author·생성 크레딧 금지.
- 현재 의도된 `feat/semantic-zoning` upstream에 검증된 마일스톤 일반 push.
  보호 설정 우회/force push 금지. 예전 오너 예외를 새 문서의 보호 정책보다 우선하지 않음.
- 생성물은 workspace `artifacts/visual` 아래 목적/버전 이름으로, 소스 Git에 넣지 않음.
  기존 산출물 삭제/최종 이름 남발 금지. unrelated 사용자 변경/빌드 캐시 보존.
- 대상 저장소 코드 실행/설치/빌드 금지, 무LLM·로컬·정적·결정성·근거 원칙 유지.
- 관련 레이아웃/렌더 변경 직후 실제 출력 검증, 매 세 작업 이내/종료 시 전체 체크포인트.

터널은 여전히 실제 관계가 사용할 때만 시공한다. 이번 실제 코퍼스는 후보0개로,
새 지형에서 실제 터널 시공까지 확인했다고 주장하지 않는다.

## CAMPUS 다음 — 건물 배정 전 내부 보행 접면 재계획

2026-10-19, ADR-050. `--campus-style organic` / campus-plan/0.5는 기존 직선 날개를
다 만든 뒤 돌리는 방식이 아니다. 중정·연결 보행축·완만하게 벌어지는 가지를 먼저
예약하고, 실제 길의 접선에 맞춰 원래 크기의 필지를 배치한 뒤 전체 원본 멤버를 넣는다.
근거 동네/혼합 멤버/관계 친밀도와 외부 차량 간선, 자연 지형은 보존한다.

새 모양 수용이 안 되면 이유를 기록하고 기존 전체 동네 계획을 유지한다. 작은 공원
패치로 축소해 성공으로 표시하지 않는다. 48→49파일 검사에서 곡선 길이를 인원수에
연동하면 기존 회전까지 흔들리는 것을 확인하여 고정 지역 예약으로 수정했다.
기존48개 전체 프레임을 보존하는 회귀 검사를 추가했다. 기존 모드는 계속 비교 가능하다.
실제 렌더·교차 저장소 결과와 제한은 이번 품질 체크포인트에 별도로 기록한다.

## 사용자 보정 — 방사형 반복과 통합 시설 회귀

2026-10-19, ADR-051/052.0.5는 사각 반복을 타원 중정+고정6방향 가지 반복으로
바꿨을 뿐이라는 사용자 평가를 수용한다. 각도 수·기하 검사 통과가 시각적 수용을
의미하지 않았다.0.5는 재현용으로만 유지한다. 새0.6 `fabric`은 실제 인접 길의
방향과 구획 안에서 긴 보행축·열린 안뜰·엇갈린 정원길 및 다른 중정 윤곽을 조합한다.
새 근거/가짜 건물 없이 전체 원본 동네를 수용하며 실패 시0.4/0.3 전체 계획으로
돌아간다. GJ136/OJ64 프레임만 바뀌고 그 밖의 배치와 자연·원본 관계는 보존한다.

회전 건물 제외 가드에 World의 모든 건물이 걸리면서 기존 게이트/테스트 집계가
전부 사라지는 회귀도 확인했다. 가드를 없애지 않고 실제 회전 필지·다른 원본 건물·
도로·자연·중정·모듈/동네 경계를 검사하는 표현 전용 집계를 복원했다. GJ3시설12파일,
OJ4시설18파일이 조건을 통과했다. 모든 확대 단계에서 유지하며 명시적 펼치기·원본
멤버/근거 보기·필터·개별 원본 경로를 실제 WebGL에서 검증했다. PB/SQLite에는
근거 없는 시설을 만들지 않는다. 집계만의 변화는 World/City/UCG/planning 바이트까지
동일한 별도 비교로 확인했다.

최종 비교 `campus-fabric-reviewed-r2/index.html`, 집계만 `world-compounds-reviewed-r2/index.html`.
3가지 구성도 여전히 제한된 문법이며, 외곽 반복 행·서비스 접근·강변 캠퍼스의 모든
변형이 해결됐다고 주장하지 않는다. 다음에는 기존 집계/필터/펼치기 기능까지 함께
확인하고 새 배치가 시각적으로 거절되면 검사 수로 정당화하지 않는다.

## 본류·지류 형태와 개수 — 수계 생성 단계 수정

2026-10-19, ADR-053. 사용자가 지적한 것은 수면 누락이 아니라 본류·지류의 반복이다.
기존 실제4저장소는 모두 본류1+3점 지류1이었고 큰 지형의 시드 테스트만으로
다양화를 검증했다고 판단한 것이 부족했다. 캠퍼스 변경으로 수면이 달라진 회귀와
구별하되, 실제 결과의 획일성을 부정하지 않는다.

새 명시 모드 `--terrain watershed-landscape`는 본류1..2/지류0..3과 지류끼리의
합류를 지형 먼저 계획한다. 합류 위치·분기 각도·폭·굽이와 점 개수가 지역 시드로
달라지고, 실제 수용할 수 없는 가지는 제한된 후보 검사에서 거부한다. 단순히 Y자
전체를 돌리는 것이 아니다. 호수·산/능선·교량/조건부 터널을 유지한다. 본류 두 개는
독립 관통 하천이며 반드시 서로 합류하지 않는다. 모든 도시가 지류를 갖거나 산을
관통해야 하는 것은 아니다. 실측 수문 시뮬레이션 또는 무제한 임의 배치를 주장하지 않는다.

원본 소스와 의존성 ID는 보존하되 자연이 먼저이므로 구역/건물/길은 재배치된다.
과거 모드는 바꾸지 않고 같은 시드/새 모드의 반복·힌트 성장·실제4저장소 결과를
별도로 검증한다. `waterways`의 MAIN/TRIBUTARY와 parentId로 개수/분기를 기록하고
여러 RIVER 노면 조각을 여러 강으로 세지 않는다. 전체 린트의 기존 위반은 별도
부채이며, 이번 변경으로 위반을 늘리거나 검사를 완화하지 않는다.
