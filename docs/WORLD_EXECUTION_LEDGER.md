# 월드 생성 — 누적 요구사항과 실행 기준

2026-10-19 정리. 중간 피드백은 기존 요청을 지우지 않는다. 새 작업을 시작할 때
이 문서의 미완료 항목과 현재 작업을 함께 확인한다. 기능 완료와 시각적 채택은 별개다.
이 문서는 요구사항/순서의 색인이고, 데이터 계약은 세 기본 명세와 승인된 ADR이 우선한다.

## 1. 읽을 문서와 현재 상태

- 기본 계약: workspace `MetropoGits_Docs/02_TECHNICAL_SPEC.md`,
  `03_FUNCTIONAL_SPEC.md`, `01_PRODUCT_PLAN.md`, workspace `AGENTS.md`.
- 확장 원안: 같은 폴더의 `MetropoGits_Procedural_World_Generation_Plan.md`,
  `MetropoGits_Hierarchical_Voronoi_Semantic_Zoning_Design.md`.
- 구현 계약: [CURRENT_BASELINE](contracts/CURRENT_BASELINE.md), ADR-024~029.
- 상세 맥락: [SEMANTIC_ZONING_PLAN](SEMANTIC_ZONING_PLAN.md),
  [URBAN_BLOCK_PLAN](URBAN_BLOCK_PLAN.md), [QUALITY_LOG](QUALITY_LOG.md).
- 기본 City/UCG 파이프라인은 유지. 새 월드 엔진은 명시적인 opt-in 실험이다.
- `semantic`은 근거 있는 동네 분할에는 성공했지만 순수 역할 분리/GRID 폴백이 강하다.
- `soft`는 관계 거리 최적화/패턴 보존에는 성공했지만 **시각적 기준안으로는 기각**.
  큰길은 그대로인 패턴 위에서 파일만 교환했고, 역할 중심에 해당 핵심 파일이 없는
  경우까지 생겼다. 이 결과를 최신 권장안이나 완료된 자연스러운 도시로 취급하지 않는다.
- 사용자가 예전 탭을 열고 있을 수 있다. 산출물 이름/버전/실제 실행 경로를 구분한다.

## 3. 이번에 바로 할 작업 — W-03/04/05/06 묶음

생성 순서:

`원본 서비스 소유권 → 근거 있는 동네 핵심+연관 파일 → 토지 배분 →
패턴과 독립적인 접근 간선/블록 절단 → 로컬 문법/필지 → 회전 건물 → 원본 관계 라우팅`

첫 세로 조각은 평지/볼록 커널 안에서 만든다. 의미 동네의 핵심 파일은 보존하고,
보조 멤버의 합류는 실제 edge ID로 설명한다. 역할을 새로 부여하지 않는다.
큰길/블록 경계를 먼저 계산하고, 기존 다섯 문법은 작은 로컬 공간에만 적용한다.
기존 모드의 의미/바이트를 조용히 바꾸지 않고 새로운 opt-in 버전으로 비교한다.
모든 Voronoi 경계를 도로로 칠하는 방식은 쓰지 않는다.

필수 회귀 검사:

- 역할 중심의 핵심 파일이 실제 동네 안에 있는가; 보조 멤버의 근거 edge는 유효한가.
- 패턴 변경과 건물 배치 전에도 주요 도로/블록이 존재하며, 로컬 패턴 변경으로
  주요 도로망 전체가 재생성되지 않는가.
- 블록은 실제 도로와 경계로 정의되는가. 완전한 도로 폐합이 아닌 외곽/행정 경계는
  그 사실을 명시하고, 단순 셀이나 AABB를 도로로 둘러싸인 블록이라고 속이지 않는가.
- 같은 입력의 바이트 일치, 실제 소규모 수정 힌트 안정성, 전체 건물·edge 보존,
  필지/건물/전폭 도로 충돌0, 전 입구 접근성을 확인했는가.
- GJ/OJ + unknown 코퍼스의 실제 Overview/District/Detail/CPU/Canvas를 보았는가.
- 실제 차이가 눈에 보이는가. 관계 거리/각도 엔트로피/테스트 수만으로 완료하지 않기.

## 4. 작업 순서와 중단 규칙

1. 이 누적 문서와 좁은 구현 결정 기록 → 별도 docs 커밋.
2. 동네 핵심/근거와 패턴 독립적 큰길·블록의 실동작 세로 조각 → 체크포인트/커밋.
3. 실제 결과에서 구조적 결함 우선 수정. 패턴 종류/곡선 미세조정에 매몰되지 않기.
4. 구조가 읽힐 때 W-15 재질 분리, 이후 LOD/아키타입/윤곽·지형 확장 순으로 재평가.

피드백이 오면 기존 W 항목을 삭제하지 않고 `유지/수정/대기/기각`을 갱신한다.
새 약속은 이 문서와 품질 로그에 남긴다. 미완료를 최종/완성/개선 성공으로 부르지 않는다.
저효율 미세 최적화가 반복되면 그 자리에서 전체 화면과 기준을 재확인한다.

## 5. 실행·전달 규칙

- 작업 단위마다 테스트 후 별도 conventional commit, 본문 bullet 필수.
- 기존 인간 Git identity 유지, 에이전트/봇/AI 기여자·co-author·생성 크레딧 금지.
- 현재 의도된 `feat/semantic-zoning` upstream에 검증된 마일스톤 일반 push.
  보호 설정 우회/force push 금지. 예전 오너 예외를 새 문서의 보호 정책보다 우선하지 않음.
- 생성물은 workspace `artifacts/visual` 아래 목적/버전 이름으로, 소스 Git에 넣지 않음.
  기존 산출물 삭제/최종 이름 남발 금지. unrelated 사용자 변경/빌드 캐시 보존.
- 대상 저장소 코드 실행/설치/빌드 금지, 무LLM·로컬·정적·결정성·근거 원칙 유지.
- 관련 레이아웃/렌더 변경 직후 실제 출력 검증, 매 세 작업 이내/종료 시 전체 체크포인트.

## 6. 진행 기록

- 2026-10-19: 누적 요구 통합. hard sorting과 district-wide soft swapping을 동시에
  기준안에서 배제. 재질 작업을 잊은 게 아니라 구조 작업 뒤로 명시적으로 보류.
  다음 구현은 W-03/04/05/06이며, 이 문서 작성만으로 구현 완료로 처리하지 않는다.
- 2026-10-19 후속 구현: `--zoning neighborhoods` 첫 세로 조각 구현/검증.
  근거 핵심 파일 실제 잔류, edge ID가 있는 미분류 보조 파일 합류, 도로 절단 블록,
  패턴과 독립적인 주요 도로, 블록별 접도/회전 배치를 연결했다. 감자박스13동네/
  29블록, 감자OJ11동네/16블록. 전체 GJ 문법을 GRID로 바꿔452개 건물 프레임이
  달라져도 큰길·블록·외곽은 같음을 실제 대형 입력으로 검증했다.
- **부분 완료 구분:** W-04의 핵심 소실은 방지했지만 W-03의 폭넓은 역할 혼합은
  미분류 helper의 근거 합류까지만 구현. W-05/06은 도로 절단 개발 블록 단계이고
  임의 도로망의 완전 폐합 면 추출은 미완료. 모든 문법이 매 도시에서 유지되지는 않음.
- **새로 확인한 회귀:** W-12 토지 면적은 soft 대비 GJ25.5%/OJ17.7%/PB9.1%/
  SQLite36.1% 증가. 로컬 접도 여유와 용량 보증 비용이다. 밀도 개선 성공으로
  포장하지 않는다. 도로/바닥 대비 부족은 실제 WebGL/Canvas를 보고 수정했다.
- 다음 우선순위: 근거 핵심과 도로 우선 구조를 유지하며 블록/접도 용량 효율 개선,
  역할별 줄세우기를 완화하는 관계 기반 혼합 확장. W-15 재질, W-13/14 LOD,
  W-19 윤곽/지형은 여전히 대기이며 삭제/완료 처리하지 않음.
- 검증/경로: `neighborhoods-r4` 전후 생성물, `neighborhoods-reviewed-r4` 실제 브라우저,
  `neighborhoods-canvas-r4` 폴백, 상세 명령/판정은 QUALITY_LOG의 해당 체크포인트.
- 2026-10-19 추가 피드백: r4에서 큰 패턴이 사라진 점을 우선 수정한다. 도로 낭비
  미세 최적화보다 **큰 가로 패턴 → 물리적 근거 동네 분할 → 접도 건물**을 먼저
  비교한다. ADR-031의 district-scale 실험은 중심/위상/축을 공유하며 세부 동네에서
  패턴을 다시 시작하지 않는다. 기존 core/helper 근거·실제 공간 소유권을 유지한다.
  패턴을 보이게 한다고 core가 없는 soft 참고 영역으로 되돌리지 않는다.
- 후속 구현: `--pattern-scale district`로 큰 도로장을 한 번만 예약하고 동네가 같은
  중심·위상·접도 후보지를 상속하게 했다. 기존 block 모드는 그대로 유지한다.
  새 결과 `inherited-patterns-r3`에서 GJ13/OJ11 동네와 핵심224/267,
  근거 helper102/45가 실제 영역 안에 잔류한다. 명시적 다섯 문법 atlas도 제공한다.
  이 실험의 동네 경계는 행정적 개발 sector이지 폐합 도로 블록이 아니다.
- 한계: 큰 패턴 보존은 개선했지만 역할 색상별 군집과 규칙적인 건물 행은 남는다.
  면적은 r4 대비 GJ약10.5%/SQLite약21.9% 감소, OJ약6.9%/PB약9.7% 증가다.
  모든 레포의 밀도 개선으로 주장하지 않는다. W-03 혼합 확장, W-15 재질, W-13/14,
  W-19는 계속 대기. 작은 Spring의 WebGL 공유도로 포인터 표적 검사는 미통과이며
  입력→CPU/World·Canvas 근거 탐색/접근·경로 검사 결과와 구분해 품질 로그에 기록한다.
