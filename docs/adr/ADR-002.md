# ADR-002: Browser-native WebGL viewer runtime

- Status: Accepted
- Date: 2026-10-17
- Decision owners: Project maintainer
- Applies to: Interactive 3D viewer runtime and packaging

## Context

The technical specification reserved ADR-002 for the city viewer runtime and
listed Three.js or React Three Fiber as candidates. MetropoGits must also open
directly from `file:`, work below arbitrary static-host subpaths, remain usable
offline after installation, avoid a JavaScript build tool in the Python release
path, and retain a dependency-free CPU fallback.

The City Scene contains intentionally simple primitives: rectangular districts,
box buildings, and polylines. The required v1 interactions do not need a general
asset, animation, or physically based material engine.

## Decision

Implement the official 3D path in project-authored browser-native JavaScript
using WebGL and the platform DOM APIs.

- The renderer uses perspective projection, depth testing, GPU-drawn extruded
  buildings and districts, camera orbit/zoom, picking, and evidence inspection.
- It consumes only the existing City Scene and UCG data embedded in the static
  artifact. It performs no network request and requires no bundler at runtime.
- The current 2D canvas viewer remains the automatic fallback when WebGL context
  creation or shader initialization fails.
- Renderer math that can be tested without a GPU is exposed through a small,
  deterministic helper API and checked under Node.js.
- Browser smoke and screenshot checks verify the actual WebGL path separately
  from the CPU-only CI preview contract.

## Why not Three.js or React Three Fiber

Those libraries remain valid future options if measured complexity warrants
them, but the v1 scene does not justify their bundle and build surface. A raw
WebGL implementation preserves direct-file loading and avoids vendoring a large
third-party artifact. This is an implementation choice, not permission to
weaken DEC-009: the result must still be a genuine interactive 3D renderer.

## Consequences

- No new runtime dependency, external CDN, npm lock, or third-party NOTICE is
  introduced by the 3D renderer.
- Shader and matrix code becomes project-owned and therefore requires focused
  tests, clear bounds, and conservative feature scope.
- Adding complex models, textures, or effects later requires a new dependency
  and asset review; it must not compromise the deterministic SVG renderer.
