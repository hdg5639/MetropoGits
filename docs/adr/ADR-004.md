# ADR-004: Hierarchical paged spatial allocator

- Status: Accepted
- Date: 2026-10-17
- Decision owners: Project maintainer
- Applies to: City Scene layout after `anchored-directory/0.1`

## Context

The first layout implementation is deterministic for identical inputs, but its
flat 8 by 8 district grid and sorted linear probing do not satisfy the complete
directory-first layout contract. A newly inserted identifier can take an
existing probe slot, directories are not spatially nested in their parents,
and more than 64 files can place buildings outside a district. The current
validator checks references but not geometric containment.

The technical specification requires directory-owned geography, bounded growth
reserves, deterministic collision handling, optional previous-scene hints, and
fixture-based churn measurements. Exact stability for every cold layout is not
possible when finite collision-free space must also remain compact, so the
allocator needs an explicit stability boundary.

## Decision drivers

- Fixed inputs must produce byte-identical canonical scenes.
- A directory subtree must own a real spatial boundary, not only a `parentId`.
- Every building and child district must remain inside its parent district.
- Adding an item should not trigger global compaction.
- A valid previous scene should preserve unaffected positions across revisions.
- Capacity must grow beyond 64 files without overlaps or out-of-bounds geometry.
- Invalid or stale hints must never make an otherwise valid layout fail.

## Decision

Replace `anchored-directory/0.1` with a hierarchical paged allocator identified
as `hierarchical-paged/1.0`, followed by the compact hierarchy revision
`hierarchical-paged/1.1` and the readable building-footprint revision
`hierarchical-paged/1.2`, followed by the balanced sibling-packing revision
`hierarchical-paged/1.3`, followed by the sparse cold-footprint revision
`hierarchical-paged/1.4`. Its output remains the existing `city/0.1`
contract unless implementation proves that additional persisted fields are
required; any such field requires a separately reviewed schema migration.

### 1. Mirror the directory tree in geometry

Build a directory tree from UCG `CONTAINS` relations and lay it out recursively.
The synthetic repository root is the outermost district. Each directory is a
district whose rectangle contains its direct file buildings and direct child
district rectangles, including fixed padding. Scene coordinates remain
absolute, but allocation calculations use coordinates local to the parent.

Sibling districts and buildings must not overlap. Graph communities and edge
traffic do not influence canonical coordinates.

### 2. Use fixed pages and reserved footprints

Each district owns separate page-aligned zones for direct buildings and child
districts. A page contains a fixed 8 by 8 cell grid. More pages are appended in
positive local coordinate order; existing page origins and cell dimensions do
not change when capacity grows.

District footprints reserve at least one unused page beyond current demand.
Child district reservations grow to the next page-aligned power-of-two
footprint. Growth consumes the reservation first. The allocator never performs
global compaction; if a reservation is exhausted, relocation is confined to the
changed subtree and any directly conflicting items in the same parent.

Version 1.1 assigns no building page to a directory without direct files. An
empty directory with exactly one child shares that child's footprint, while
multiple child districts use deterministic row packing. Renderers omit the
redundant boundary of a footprint-sharing directory but retain the complete
directory hierarchy in the City Scene and inspector data. Version 1.0 scenes
remain schema-valid, but are intentionally ineligible as 1.1 position hints so
the oversized empty-directory reservations cannot survive migration.

Version 1.2 expands each building from a 4 by 4 footprint to 6 by 6 within its
unchanged 7-unit stable cell and increases archetype heights. This leaves at
least one unit between neighboring buildings while making city-wide views
legible. Earlier hierarchical scenes remain schema-valid but are not reused as
1.2 hints because persisted building geometry belongs to the layout contract.

Version 1.3 gives the deterministic sibling row target a small width bias. This
prevents one tall child from forcing all later, shorter siblings into a second
full-height row and produces a more balanced city footprint. Stable 1.3 hints
still lock eligible child anchors before new districts are packed.

Version 1.4 removes unused leading rows and columns from each occupied cold
page and sizes the final page to its actual occupied cells, with a 24 by 24
minimum lot. Existing positions remain locked when a valid 1.4 hint is supplied;
new files may consume more whitespace rather than moving those anchors. The
viewer also caps its initial fit scale so a single tall building does not fill
the viewport. Earlier scenes remain valid but are intentionally ineligible as
1.4 hints because their district footprints encode the older fixed-page view.

### 3. Allocate deterministically within a page

The home cell and probe stride come from separate portions of SHA-256 over the
stable entity or district ID. The stride must be odd so every cell in a page is
visited. Cold allocation processes canonical stable IDs and probes the current
page before opening the next page.

This rule guarantees identical output for identical inputs. Without a previous
scene, insertion into a colliding probe cluster may move members of that local
cluster. That cold-layout exception is accepted, must be measured, and must not
move unrelated districts.

### 4. Treat a previous scene as a hint, never authority

`generate_city` will accept an optional previous City Scene. A hint is eligible
only when its schema and layout algorithm family are supported and its IDs,
coordinates, dimensions, and parent relationships are finite and internally
consistent.

Eligible positions for still-existing IDs are locked first when they remain
inside the correct parent reservation and do not conflict. New and ineligible
items are then placed by the deterministic page allocator. Conflicting, stale,
or malformed hints are ignored deterministically and reported through build
diagnostics; they cannot override the current UCG or bypass City validation.

### 5. Validate geometry at the contract boundary

City validation must reject:

- a building outside its referenced district;
- a child district outside its parent district;
- overlapping sibling districts;
- overlapping buildings in one district;
- non-finite or non-positive geometry; and
- a scene whose declared layout algorithm is inconsistent with supplied hints.

Network paths may cross district boundaries and are not containment subjects.

## Churn acceptance gates

Implementation of this ADR is incomplete until automated fixtures demonstrate:

1. identical inputs produce identical canonical scene bytes;
2. adding one file with a valid previous-scene hint moves zero existing
   buildings and zero district anchors;
3. adding one directory with a valid hint moves zero entities outside the
   modified ancestor subtree;
4. a cold-layout collision fixture documents moves only inside its collision
   cluster and leaves unrelated district anchors unchanged;
5. directories containing 65, 100, and at least 1,000 files keep every building
   inside bounds without overlap; and
6. malformed hints are safely ignored and produce the same valid geometry as a
   cold layout.

The test suite must report moved existing IDs, total compared IDs, and churn
ratio when a gate fails so allocator changes remain reviewable.

## Alternatives considered

### Keep sorted linear probing

Rejected because insertion order can move existing occupants and unbounded
linear overflow leaves the fixed district rectangle.

### Repack every district with a compact grid

Rejected because minor additions can move most buildings and propagate changes
through ancestor layouts.

### Use graph community layout as canonical geography

Rejected by DEC-007 because small relationship changes can reshuffle the whole
city. Communities may remain a non-authoritative overlay.

### Require previous scenes for all builds

Rejected because clean builds and CI must remain reproducible from source and
pinned options alone. Hints improve continuity but are optional.

## Consequences

- The layout module becomes tree-aware and accepts an optional hint input.
- Districts may use more whitespace in exchange for bounded local growth.
- Cold layouts retain a documented local collision exception; hinted layouts
  provide the stronger continuity guarantee.
- The validator and fixtures must be upgraded before DEC-007, FR-006, and
  AC-003 can move out of `BLOCKED` state.
- Changing page dimensions, hash inputs, probing, padding, or reservation rules
  requires a new layout algorithm version and churn comparison fixtures.

## Rollout

1. Add failing churn, containment, overlap, capacity, and invalid-hint fixtures.
2. Add geometric validation without accepting invalid generated scenes.
3. Implement recursive page allocation and previous-scene hint handling.
4. Regenerate canonical fixtures and document the layout version migration.
5. Re-audit DEC-007 and only then update release readiness statuses.
