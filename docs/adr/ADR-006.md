# ADR-006: Apache License 2.0

- Status: Accepted
- Date: 2026-10-17
- Decision owners: Project maintainer
- Applies to: MetropoGits source, documentation, and accepted contributions

## Context

MetropoGits is intended to become an open-source tool that permits commercial
use and community contribution. The repository previously withheld a license,
so copyright permission and contribution terms were intentionally unresolved.
The project also analyzes technology signatures, which makes an explicit
patent-license grant preferable to an implicit or custom policy.

## Decision

MetropoGits is licensed under the Apache License, Version 2.0. The unmodified
official license text is stored in the repository-root [`LICENSE`](../../LICENSE)
file and package metadata identifies that file.

Contributions intentionally submitted for inclusion are accepted under the
same terms unless the contributor explicitly states otherwise, as described by
Section 5 of the license. Third-party dependencies, copied assets, and catalog
sources remain under their own terms and must be reviewed before inclusion.

## Current compatibility review

- The pinned Python runtime, build, and development distributions declare MIT
  or PSF-2.0 terms; their versions and purposes are listed in
  [`DEPENDENCY_INVENTORY.md`](../DEPENDENCY_INVENTORY.md).
- The static viewer currently bundles only project-authored HTML, CSS, and
  JavaScript. It contains no vendored framework, font, image, or model asset.
- Catalog releases contain project-authored declarative matching rules and
  synthetic fixtures rather than copied third-party implementation code.
- No third-party attribution currently requires a repository-root `NOTICE`
  file. This conclusion must be revisited when a renderer library, model,
  texture, font, or other vendored asset is added.

This review records repository evidence and is not legal advice.

## Consequences

- The missing-project-license release blocker is resolved.
- Public deployment remains separately deferred and blocked; adding a license
  does not make the private repository public or publish generated metadata.
- Dependency and asset additions require license compatibility and NOTICE
  review in the same work unit.
