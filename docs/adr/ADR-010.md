# ADR-010: Hierarchical street reserves and evidence-route routing

- Status: Accepted
- Date: 2026-10-17
- Decision owners: Project maintainer
- Applies to: layout spacing, visual street derivation, and network routing

## Context

Layout 1.11 allows concave sibling footprints to reuse one another's empty
bounding-box corners, but it permits those footprints to touch. With a
seven-unit allocation cell and seven-unit building spacing, the result reads as
one continuous parcel made from file-sized tiles. The 135 GJ-Cloud networks are
also three-point L shapes between aggregate centers, so they cross buildings
and resemble circuit traces instead of transport routes.

The City Scene already models a network path as an arbitrary polyline and
retains every contributing UCG edge ID. Route shape and renderer width can
therefore improve without changing the `city/0.2` schema or logical graph.
Street surfaces themselves are structural visualization, not evidence that a
source relationship exists, and must be visually distinguished from the
evidence-backed routes that use them.

## Decision

Introduce layout `hierarchical-paged/1.12` with a deterministic street grid.

- Sibling packing reserves two allocation cells between children of the root,
  one cell between shallow package/module groups, and no additional cell for
  deep leaf siblings. At the current seven-unit grid this yields approximately
  14-unit boulevards, seven-unit streets, and shared deep parcel seams.
- Empty directory chains still share their single child's footprint. The
  hierarchy is preserved without manufacturing a road at every path segment.
- Structural street cells are derived from the portion of a parent footprint
  not owned by a direct child footprint or direct file building. Routed
  corridors are included so every evidence route has a visible road bed.
- Structural streets are viewer/preview projection data. They are neutral,
  non-selectable, and labelled as visual infrastructure in the legend. They do
  not contain edge IDs and cannot be presented as an observed dependency.
- Network endpoints use deterministic access cells nearest the mean position of
  the contributing source and target buildings. Routing uses a fixed-neighbor
  shortest-path search on the allocation grid, avoids every file-building
  obstacle cell, and simplifies only collinear points.
- If the street graph is disconnected, the router may add the minimum
  deterministic non-building corridor required to join the two access cells.
  It must never route through a building footprint.
- Evidence-route width is a renderer projection of `len(edgeIds)` using a
  bounded logarithmic scale. Network IDs, kinds, contributing edge IDs, and
  inspector behavior are unchanged.

## Stability and compatibility

- City Scene remains `city/0.2`; only the layout algorithm version changes.
- Layout 1.12 accepts only 1.12 placement hints. A 1.11 scene is rejected as a
  hint because its sibling anchors do not reserve the new street widths.
- Fixed inputs, options, and compatible hints must produce byte-identical City,
  street projection, SVG, and viewer assets.
- Edge aggregation remains deterministic and source-evidenced. A visual street
  never creates, deletes, or changes a UCG relationship.

## Required measurements

Quality checkpoints for this layout record:

- root AABB and occupied-land density;
- hierarchy-level street width distribution;
- percentage of routed length intersecting a building rectangle, required to
  be zero;
- route vertex-count distribution and edge-count aggregation;
- small-change placement churn and double-run byte equality.

## Alternatives considered

### Continue drawing direct L-shaped links

Rejected because the shortest geometric L routinely crosses buildings and
does not use the empty space intentionally reserved by layout.

### Render every UCG edge as its own road

Rejected because it would discard the existing aggregation contract and make
large repositories less readable.

### Encode streets as semantic City decorations

Rejected because streets are derived presentation infrastructure, not source
facts. Keeping them in packaged projection data prevents them from being
mistaken for UCG-backed architecture.

### Reserve the same road width at every directory depth

Rejected because ten-level source paths would accumulate large empty fields.
Hierarchy-sensitive spacing gives major modules visible separation while deep
packages remain compact.

## Consequences

- Major services read as city blocks separated by continuous boulevards rather
  than touching jigsaw pieces.
- Evidence routes may contain more vertices, but remain bounded by the scene
  grid and retain exact contributing edge IDs.
- Canonical coordinates change at the 1.11 to 1.12 boundary. Later 1.12 hints
  restore stability under unchanged or small inputs.
- Small leaf-directory consolidation and block-level overview LOD remain
  separate follow-up work; this decision establishes the road space they use.
