# ADR-011: Compact blocks for small leaf districts

- Status: Accepted
- Date: 2026-10-18
- Decision owners: Project maintainer
- Applies to: deep leaf-district packing and layout hints

## Context

Layout 1.12 reserves hierarchy-aware streets and routes evidence networks around
buildings, but every leaf directory still reserves its own padded parcel. In
GJ-Cloud, 224 leaf districts contain only one to three files, and 141 of those
belong to sibling groups. Repeating an independently padded footprint for each
small directory creates jagged edges and consumes land without adding semantic
information.

Directory identity cannot be discarded: DEC-008 requires every directory to
remain a district, and selection must continue to resolve each file and
district to canonical source facts. Top-level service boundaries also must not
be collapsed merely because a service happens to contain few files.

## Decision

Introduce layout `hierarchical-paged/1.13` with compact deep-leaf blocks.

- A block candidate is a group of at least two sibling leaf districts, each
  containing one to three direct file buildings, whose parent is below the
  hierarchy levels that receive explicit boulevard or street reserves.
- Candidate leaf buildings align inside seven-unit parcel cells with a
  half-unit inset. A six-unit building therefore occupies one parcel instead
  of straddling four allocation cells. Other districts retain the existing
  building inset and layout behavior.
- Candidate siblings are packed deterministically as one balanced composite.
  The composite reserves its rectangular envelope once; cells between its
  member districts are parent-owned visual alleys rather than fabricated
  districts or source relationships.
- Every member retains its canonical district ID, parent ID, footprint,
  building membership, inspector behavior, and source evidence. The composite
  block is layout infrastructure only and is not added to UCG or City Scene as
  a semantic entity.
- Top-level modules and shallow package groups are excluded. Their layout 1.12
  boulevard and street separation remains authoritative.
- At the repository root, packing may trade at most 12 percent of the shortest
  achievable long side for the lowest AABB area. This bounded density pass
  prevents smaller leaf blocks from creating a larger central void while
  retaining a balanced city silhouette.
- Compatible previous-scene hints preserve member offsets within a block.
  New members fill deterministic free parcels without relocating valid hinted
  members when the existing block has capacity.

## Stability and compatibility

- City Scene remains `city/0.2`; no schema, identity, evidence, or network
  contract changes.
- Layout 1.13 accepts only 1.13 placement hints. Layout 1.12 hints are rejected
  because compact-leaf building insets and composite envelopes differ.
- Fixed inputs and compatible hints must produce byte-identical City and
  renderer artifacts.
- Small-change tests cover adding a new leaf sibling to an existing block and
  require unchanged coordinates for existing members when a free parcel is
  available.

## Required measurements

Quality checkpoints for this layout record:

- eligible leaf count and sibling-block count;
- member-footprint area divided by each block AABB area;
- block size distribution and root AABB change;
- sibling footprint overlap count, required to be zero;
- evidence-route/building intersection count, required to remain zero;
- cold/hinted byte equality and small-change member churn.

## Alternatives considered

### Remove small directory districts

Rejected because it violates the directory-first model and breaks canonical
district inspection.

### Compact every leaf directory, including top-level services

Rejected because repository and service boundaries carry more spatial meaning
than a small file count. Major modules keep explicit road separation.

### Add a semantic block entity to City Scene

Rejected because the block is a visual allocation device, not a repository
fact. Adding it would require an unnecessary schema and identity change.

### Keep the three-unit inset for every small leaf

Rejected because a six-unit building then straddles four seven-unit cells,
preserving the repeated empty parcel that this decision is intended to remove.

## Consequences

- Dense package trees use fewer jagged one-directory islands and read as
  rectangular urban blocks separated by narrow alleys.
- Some coordinates change at the 1.12 to 1.13 boundary; subsequent compatible
  hints restore incremental stability.
- The overview still needs block-level semantic LOD. This decision creates the
  canonical compact geometry that the later LOD projection can summarize.
