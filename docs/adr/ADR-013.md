# ADR-013: Deterministic README showcase projection

- Status: Accepted; implemented 2026-10-18
- Date: 2026-10-18
- Applies to: static preview composition, build artifacts, README snippet
- Requirements: DEC-005, DEC-006, DEC-008, DEC-009, DEC-011;
  FR-007, FR-011, FR-012; AC-002, AC-006, AC-011, AC-014

## Context

GJ-Cloud and GamjaOJ already produce distinct, inspectable cities. The detailed
static SVG still shows every file and network at once, while WebGL overview
uses traceable block aggregates. Long city bounds and dense reference lines
make the README image difficult to read. A small Spring fixture also reveals
a district surface covering the SVG header: fitting building bounds alone is
not sufficient to protect the complete composition.

ADR-012 establishes visual aggregates with complete membership. ADR-010
distinguishes structural streets from evidenced networks. A showcase should
reuse these meanings without changing canonical geography or inventing facts.

## Decision

Add a CPU-only deterministic `showcase.svg` alongside the existing detailed
`preview.svg`. Both consume the same validated City Scene and UCG. No new UCG
or City field, entity, stable ID, role, or network edge is introduced.

The implementation emits both previews. `render --mode showcase` selects the
new CPU projection, and `build` integrates it into the manifest and README
snippet. See [Showcase rendering](../SHOWCASE.md) and the quality log for
observed results and remaining visual work.

### Artifact and command compatibility

| Surface | Intended behavior |
| --- | --- |
| `build` | Emit both `preview.svg` and `showcase.svg` |
| `render` | Add `--mode detail\|showcase`; default remains `detail` |
| `render --mode showcase` | Use the existing explicit scene, graph, output, width and height arguments |
| Manifest | Add the showcase path, MIME type, byte size and checksum using the existing artifact record shape |
| `README_SNIPPET.md` | Link the showcase image to `index.html` once showcase validation passes |
| Viewer fallback | Preserve the existing detailed `preview.svg` link |
| Composite Action | Return its existing artifact-directory output; include showcase in that directory |
| History / metropolis | Keep their current output behavior; extending P2 commands is outside this work |

Old links to `preview.svg` keep working. The default showcase is 1200 by 675,
matching the existing CLI dimensions. No GPU, browser, Node runtime, remote
font, image request, or rasterization dependency is added to the CPU build.
No README is edited and no generated city is published automatically.

### Shared city and visual abstraction

- Preserve canonical district footprints, file positions, building archetypes,
  network paths, and their UCG references.
- For large cities, use ADR-012's major-district assignment, block membership,
  territory clipping, and balanced representative placement. A renderer may
  not derive a different service hierarchy merely for a better picture.
- Port the existing pure viewer derivation to the CPU renderer behind a
  projection interface. Use shared fixtures to compare JavaScript and Python
  results for block IDs, members, footprints, and representative positions.
  The runtime remains Python-only; Node is permitted in development parity
  tests, not required to generate a preview.
- Small scenes retain their real file buildings. Unknown-language scenes keep
  generic buildings and structural districts. Sparse input must not acquire
  fabricated buildings to fill the frame.
- Representative masses are explicitly labeled as visual aggregates. Their
  appearance can summarize existing archetypes but cannot imply a new service
  or claim that a whole block uses one technology.

### Traceability

SVG contains a deterministic, escaped JSON mapping in a non-executable
`metadata` element with projection version `showcase/0.1` and the UCG digest.
Presentation groups carry stable IDs that index that mapping.

- File groups map to canonical `entityId` and `districtId`.
- Block groups retain complete sorted `memberEntityIds` and
  `memberDistrictIds`, including files not individually drawn.
- Major-district groups retain canonical district IDs.
- Each displayed evidence route maps to its existing network ID and exact
  `edgeIds`. Hidden network IDs and displayed/total counts are disclosed.
- Structural street groups are labeled visual-only and do not acquire edge
  IDs or evidence records.

Metadata is a projection format, not an extension to the public City schema.
Validate every mapping against the supplied graph/scene before serialization.
Use safe SVG titles/descriptions for human-readable context. Detailed evidence
inspection remains available through the linked viewer; metadata alone is not
advertised as an interactive Inspector.

### Roads and landmarks

Draw neutral structural streets below buildings. Prioritize networks crossing
major-district boundaries; rank by descending distinct edge count and then
stable network ID. Show at most 24 networks in the large-city showcase.
For small detailed scenes, preserve all routes within that same budget.

Use existing network polylines. Omitting a route from the image changes neither
the source scene nor its logical graph. Do not redirect a line to a relocated
representative mass and imply that the mass is a real file endpoint. Disclose
that relationship routes retain canonical positions when aggregates are shown.

Existing evidence-backed archetypes supply landmark silhouettes. Do not
assign security, database, or service identities from a suggestive district
name. Keep unsupported semantics generic and distinguish structural labels
from role claims.

### Camera and composition

Use a fixed 3/4 isometric elevation and deterministic quarter-turn yaw
candidates. For each candidate, project all visible district surfaces,
streets, routes, building tops, and representative masses. Fit those bounds
inside a content rectangle that reserves explicit header, legend, and margin
space. Choose the candidate with the largest fitted projected bounding area;
break ties by a fixed yaw order.

Translation, uniform scale, and camera rotation are presentation-only. Never
stretch one world axis, move a service, or discard a district to fit 16:9.
Clip world drawing to the content rectangle and draw protected UI text last.
Label placement must stay inside the viewport and use deterministic collision
handling, with major districts taking priority over minor labels.

Measure fitted bounding-box occupancy and painted-area occupancy separately;
a large bounding box can still contain substantial empty land. Record these
with the chosen yaw and label collisions on GJ-Cloud, GamjaOJ, and a small
fixture. Do not claim one camera rotation solves all tall-layout problems.

## Implementation and validation sequence

1. Add the CPU projection boundary, parity fixtures, trace metadata and
   deterministic isometric SVG. Fix the detailed preview header defect in a
   separate focused work unit if it requires changing shared framing logic.
2. Inspect small, unknown-language, GJ-Cloud and GamjaOJ outputs at both full
   resolution and 640 by 360 thumbnail size. Require no header/legend occlusion,
   clipped building tops, block overlap or fabricated source mappings.
3. Add build/CLI/manifest/Action integration and switch the generated README
   snippet only after visual validation. Update artifact-list tests, the
   hosted Action smoke and publishing documentation together.
4. Compare repeated output bytes and verify input UCG/City hashes are unchanged.
   Record cross-runtime block parity and exact route edge membership.
5. Capture controlled WebGL comparisons under VIS-06. Performance conclusions
   require measured interaction timing and cannot be inferred from SVG output.

The screenshot check on the Spring fixture is a mandatory regression case.
Large-city outputs must retain the complete file membership of every aggregate
and report displayed versus total routes. The implementation is complete only
after actual artifacts satisfy these checks and the relevant test suite passes.

## Alternatives and tradeoffs

- Replacing `preview.svg` immediately risks existing links and detailed
  fallback behavior. An additional named artifact makes the distinction clear.
- Capturing WebGL in a browser would add a GPU/browser dependency to the static
  preview path and weaken deterministic rendering guarantees.
- Repacking the canonical city for a README aspect ratio changes geography
  between views and risks small-change stability. Camera composition comes
  first; future packing changes require their own measured layout decision.
- Python/JavaScript projection parity adds maintenance work. Shared fixture
  comparisons are required so the static and interactive cities cannot quietly
  diverge in block membership or placement.

## Deployment boundary

The repository is public under ADR-007's 2026-10-18 amendment. This renderer
decision does not enable Pages, change release readiness to READY, or publish
GJ-Cloud/GamjaOJ metadata. Those repositories are local visual test inputs;
public demo input must be reviewed separately before deployment.
