# ADR-015: Evidence-compatible role landmarks in interactive LOD

- Status: Implemented, presentation-only first slice
- Date: 2026-10-18
- Authority: maintainer request to consolidate gate and test-file clusters
- Contracts: no UCG/City schema, stable identity, canonical coordinate or edge changes

## Decision

Extend the existing block LOD with bounded role compounds. A landmark is a
visual grouping of actual file buildings, never a new service, deployed system,
test execution result or inferred dependency. DEC-005/008 remain intact.

The shared viewer policy groups at least four nearby compatible files inside
one existing spatial block and structural major district, without crossing a
known MODULE boundary. Next.js page and route-handler evidence remain separate;
Spring controller signatures remain separate; LIBRARY buildings require actual
test-source evidence before becoming test centers. Unknown/generic roles are
not promoted. No unit/integration/E2E distinction is inferred from test density.

Membership grows deterministically from stable file IDs. An enlarged footprint
absorbs all compatible occupants together, or is rejected if it covers another
file, crosses an evidenced route corridor, leaves the parent block's clipped
land, exceeds 56 world units on either axis, or has under 55% occupied area.
Each added candidate must lie within 15 units of an existing member origin.
These are presentation tuning constants, not semantic thresholds.

- 1–3 eligible members retain existing representation.
- 4–11 form a center/hall.
- 12+ form a campus/terminal, still subject to the footprint limits.
- Height grows logarithmically and is capped at 30 units; bounded wings/bays
  differentiate test campuses from gate concourses without a tower per file.

Overview shows these compounds alongside residual structural blocks. District
LOD retains compounds alongside individual buildings. Detail restores original
buildings (an explicitly selected aggregate remains pinned until exploration
or another selection). Member lists are disjoint; filtered-out files never
return through a partial aggregate. Selecting a constituent unfolds its group.
Residual block plots exclude compound footprints, preventing overlapping masses.

Hover discloses visual aggregation and sample file paths; click exposes complete
membership and grouping evidence, with keyboard-reachable file buttons. Explore
clears aggregate selection and zooms to actual files. Both WebGL and Canvas use
the same membership and compound volumes. Geometry stays cached during synthetic
activity. No graph relationships or animation routes are merged by this change.

## Limits and follow-ups

This first slice applies to interactive LOD. Detailed preview and README showcase
keep their existing representations of the same canonical city. CPU showcase
parity, additional role families, relation-assisted grouping and transition
animation require separate verification. A role compound does not fix the
known TS alias/Java nested-type misses, per-file road-access gap or HTTP/messaging
extraction gap. Those remain distinct priorities; do not fabricate connections
to make a compound look inhabited.

membership, permutation determinism, input immutability, positive/negative

The opt-in browser audit also exercises real hover/click and constituent
navigation on visible role compounds. See QUALITY_LOG for real fixture results.
