# ADR-016: Evidenced building access through a shared route graph

- Status: Implemented; visual/performance review remains iterative
- Authority: maintainer's explicit building-access/shared-road/junction request
- Scope: derived visualization data; no UCG/City schema, source ID or building relocation

Replace mean-of-building-group paths in the interactive renderer with complete
file-endpoint paths. Retain canonical network groups for compatibility and
inspection, but do not use their mean anchors as a substitute for file access.

Each resolved file pair has a deterministic route and its exact original edge
IDs. Shared segments reference those routes losslessly. A geometric crossing is
not a new semantic edge. Selecting a file uses only its incident routes, including
both endpoint spurs; synthetic markers follow one stored route without making
random choices at junctions. Filters must not leak unrelated routes through a
shared segment. Role compounds remain explicit visual aggregations of files.

The selected-path x-ray overlay follows those same ground coordinates; it is
explicitly labeled and may show through visual occluders. It is not a second
physical road above buildings. All routes restores background context while
only the selected relationships remain highlighted. At most 96 real derived
routes supply synthetic markers; hidden Overview spurs hide their markers too.

Routing uses a 3.5-unit rectilinear lattice against actual building obstacles.
Entrances terminate at building boundaries. Segment widths respect clearance;
no building-intersecting shortcut is allowed. Costs stay between 90 and 100 per
lattice step, with bounded preference for wide/existing corridors, so sharing
cannot exceed 100/90 times the shortest lattice path. This bound is relative to
the chosen access ports, not Euclidean distance or measured runtime flow.

Derived payloads are versioned separately from canonical City. Resource limits
and unreachable endpoints are explicitly reported, never replaced with invented
connections. Overview may omit local access detail; District/Detail and selection
use the actual shared network. Unsupported legacy geometry degrades explicitly.

Acceptance: exact relation coverage; zero unrelated building movement; no route
or pavement crossing building interiors; shared-segment/junction provenance;
A-to-B and C-to-D do not become A-to-D; deterministic geometry; bounded detours;
selection and animation use the same paths; actual GJ/OJ WebGL and performance
inspection, plus sparse and negative fixtures.

## Continuity refinement implemented 2026-10-18

The maintainer requested road-led blocks and parcels; see
[the staged plan](../URBAN_BLOCK_PLAN.md). Its first slice may refine derived
routing without relocating canonical buildings or changing source facts.
Track arrival direction during search so bend costs are evaluated correctly,
including source and destination access-spur headings.
Keep each transition within 90..100, including its bend cost, preserving the
100/90 shortest-lattice-path bound and existing resource ceilings. Prefer
fewer turns on equal-cost solutions; do not trade away endpoint coverage.
Derived output now records `visual-access/0.2`; its fields are unchanged and
older supplied routing payloads remain readable. Route IDs and original edge
membership persist; geometry-derived segment IDs may change. The cost is
`min(100, 98 - wideDiscount - sharingDiscount + 2 * turns)`, where wideDiscount
is 0 or 2 and sharingDiscount is 0..6. Final-step turns include the destination
spur. Equal cost favors fewer turns, then deterministic coordinate ordering.
The existing 5,000,000 expansion budget now counts directional states; some
large inputs may reach it earlier. Never raise the limit to hide this tradeoff.
Compare routes/turns/sharing on both real repositories. This does not authorize arbitrary geometry
snapping, new relationships or the later canonical block allocator.
