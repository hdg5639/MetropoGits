# ADR-017 Opt-in parcel layout export and hint compatibility

- Status: Accepted for experimental implementation; not the default layout
- Date: 2026-10-18
- Authority: maintainer approval to connect the measured parcel candidate to 3D

## Decision

Export the measured single-district parcel candidate as a real City scene through
an explicitly invoked developer command, `python -m scripts.parcel_viewer`.
Normal CLI/Action builds keep `hierarchical-paged/1.14`. The new algorithm name is
`hierarchical-parcel/0.1-experimental`, under the existing `city/0.2` fields.
Add it to the layout enum; older enum validators must update before consuming
these opt-in artifacts. Existing City versions and IDs remain unchanged.

Read an existing validated 1.14 build, recompute the bounded parcel experiment
from its UCG (never trust supplied override JSON), and change only the selected
leaf's coordinates. Keep file ownership, source facts, dimensions, all districts,
network IDs and original edge membership. If no safe candidate exists, export
the structural baseline with an explicit fallback decision in the report.

Recompute canonical aggregate network paths against the new obstacles. Then
derive the **whole city's** file-access graph, not just the pilot's incident
routes. Viewer, preview and showcase receive that same graph and scene. Export
fails if any represented relationship is lost or pavement intersects a building;
do not publish a partial experiment as a successful geometry review. Full-city
shared routing may change outside the moved district; the pilot's local metrics
do not promise whole-city routing improvements.

## Layout hints

The first opt-in exporter accepts only hints with this exact experimental
algorithm, valid City geometry, identical directory geometry/parentage, and
identical file IDs/owners/footprint dimensions. It retains every hinted X/Z
coordinate while taking current roles, heights, evidence and relations from the
new graph. Relationship-only changes do not trigger a fresh placement search.

Added/removed/renamed files, changed ownership, changed district geometry and
other layout versions are explicitly rejected as incompatible hints. The caller
must omit the hint to request a cold experiment; the exporter never silently
resets geography. Incremental growth allocation is not part of this first mode.
The normal 1.14 generator continues to reject experimental hints through its
existing diagnostic path. No scene is relabeled to bypass either compatibility
check. Cold allocation and hinted geometry have separate determinism tests.

## Consumers and delivery

The City schema/validator, static viewer, detailed SVG and showcase must accept
the new enum and preserve the same geometry and provenance. The viewer marks
experimental scenes visibly. The exporter creates a new output directory only,
with graph, scene, all bundled assets, previews, a decision report and checksums.
It never reads executable assets from the input build or publishes private data.
Do not run the target repository, install its dependencies or load its HTML.

Verify GJ and OJ full-route coverage, no geometry intersections, repeated output,
hint retention/rejection, renderer contract parity, default-build regression,
and actual WebGL selection/camera/Synthetic behavior. Compare the changed district
at the same camera as the original. Passing these checks authorizes review of
the opt-in output, not default adoption or an unrestricted city-wide reallocator.
