# ADR-024 — Experimental procedural world beside the City pipeline

Status: user-authorized implementation of the Procedural World proposal,
2026-10-19. Flat first milestone; existing default builds remain available.

## Contract and ownership

Implement `metropogits.world` independently of the cell allocator. An opt-in
developer command consumes a validated existing build (UCG and City) and emits
`world.json`, a static viewer and CPU SVG. Keep the original `city.json` and UCG
bytes unchanged. A separately versioned `world/0.1-experimental` document owns
physical polygons, streets, parcels, rotated building parts and route references.
The browser adapter is a derived view, not a City v0.2 producer or schema change.
Source directory ownership and every analyzed source building remain traceable.
Edges with non-file endpoints remain in UCG and are explicitly diagnosed rather
than invented as local trips. Both exports read the same physical world.

## Reproducible seeds

Use SHA-256 over length-prefixed UTF-8 fields, first eight digest bytes interpreted
unsigned big endian, hexadecimal 16-character seeds. Version this as
`sha256-counter/1`. Derive independent labeled streams for district and building
paths. Counter draws hash (stream seed, decimal counter), without ambient PRNG
state. Default world seed derives from repository namespace, never revision or
content digest; an explicit namespace/seed can override it. A local path-derived
UCG namespace remains machine scoped unless the user supplies a portable namespace.
Seeds affect physical presentation only; source IDs and evidence do not change.
Quantize output coordinates to 1/10000 world units and sort all identity arrays.

## Flat capacity allocation and streets first

Initially use deterministic capacity-guided polygon bisection. Each shared cut
is computed once and inherited by both children. This directly meets area demand
without a global iterative power-diagram solver in the first vertical slice.
Record the actual allocator name: do not call it Voronoi. Weighted power cells
remain an evaluated alternative. Preserve hierarchy-based principal districts;
every original directory remains in the source mapping, even when not a separate
physical city zone. District identity is structural, not inferred service behavior.

Calculate land demand from building envelopes, frontage/access space and growth
reserve. Subdivide buildable convex district land into frontage strips and local
parcels. Structural streets reserve space before building placement. Local axes
follow district boundaries; whole meshes and entrances share each parcel frame.
Connect strips to shared boundary corridors, and route real source-target pairs
over the resulting infrastructure with cached shortest-path trees. Shared physical
segments retain exact route/edge membership. No synthetic semantic relationships.

Keep explicit complexity/iteration caps, fail clearly on infeasible placement,
and preserve all source files. Layout hints may reuse a complete district only
when seed/options/ownership are compatible and reserved capacity fits. Report
replanned districts; do not claim all cold layouts are incrementally stable.

## Delivery gates

One source building per expected file, no lost UCG records, no parcel or building
overlap, full-width street clearance, reachable entrances, continuous semantic
trips and exact edge provenance. Compare repeated world/SVG bytes, changed seed,
shuffled inputs, nearby revisions and small/sparse plus large/unknown fixtures.
Run the maintained Spring pipeline and four-repository comparison, inspect real
WebGL/Canvas and CPU previews, and record stage times outside canonical artifacts.
This milestone does not implement relief, hydrology, bridges, tunnels or every
planning profile. Keep these as subsequent concrete world milestones.
