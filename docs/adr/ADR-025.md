# ADR-025 — Opt-in radial district planning

Status: implementation under the approved Procedural World Phase B plan,
2026-10-19. Additive experiment; original GRID policy remains the default.

## Outcome and boundary

Introduce `--planning mixed|radial|grid` in the procedural-world developer
command. `mixed` chooses GRID or RADIAL from an independent district seed;
the choice is a visual planning grammar, never a code-role or quality claim.
RADIAL reserves clipped polygonal orbital roads and three to five spokes before
assigning tangential, street-facing parcels. A real central junction connects
the spokes; rings are infrastructure, not fake semantic landmarks or vehicles.
Both exports and exact source-pair routing consume those same physical roads.

Keep canonical UCG/City and source IDs untouched. Existing `world/0.1-experimental`
documents remain valid. Extend its accepted generator/profile values additively:
non-default planning uses `flat-planning/0.2` and explicit `planningPolicy`.
Default GRID generation retains its previous metadata and geometry. Consumers
already read physical geometry rather than depending on the profile enum.

## Geometry and bounded fallback

Clip ring centerlines inside reserved district land. Connect clipped ring ends
to the shared boundary street, and spokes directly to that boundary. Generate
parcels only after all full-width corridors are known, rejecting conflicting
roads or parcels through a bounded spatial index. Orient each whole building
and entrance to its own ring frontage, not a decorative rotation applied later.
No building may shrink, disappear or change semantic archetype to fit.

Mixed planning falls back locally to GRID if a radial plan lacks capacity;
record that district and reason. Explicit radial planning retains the existing
bounded capacity-repair/failure protocol. Never inflate the whole world solely
to force an aesthetic profile. A previous-world hint is compatible only with
the same policy; retain prior profile decisions and slots while capacity fits.
Changing policy is an explicit geographic replan, not an incremental-stability
claim. Seed changes do not affect underlying source facts.

## Acceptance

Inspect GRID vs mixed on GJ-Cloud, GamjaOJ, PocketBase and SQLiteBrowser with
the same world seed and envelope where feasible. Record actual profile/fallback
counts and allocated land rather than claiming every district becomes radial.
Validate full-width street clearance, nonoverlapping parcels, connected doors,
exact source-edge conservation, repeat bytes, compatible small-change hints,
and unsupported-language output. Inspect real WebGL, Canvas and CPU previews.
Measure output size and generation time; existing bounded routing must remain
usable. Terrain, semantic compound LOD and additional planning grammars remain
subsequent vertical slices.
