# ADR-026 — Remaining flat-world planning grammars

Status: user-authorized ORGANIC, INDUSTRIAL and HYBRID implementation,
2026-10-19. Deliver and verify each grammar as its own work unit.

Retain the existing grid/radial/mixed policies byte-compatible. New explicit
organic/industrial/hybrid policies use `flat-planning/0.3`. A new `varied` policy
selects all five implemented grammars with independent district seeds, and
records local GRID fallback when the chosen grammar cannot accommodate demand.
Do not silently redefine the older two-grammar `mixed` policy.

ORGANIC uses sampled meandering streets, irregular row spacing and oblique
collectors. It is not merely rounded corners on an unchanged Manhattan graph.
INDUSTRIAL uses wide spines, branching service courts, wider/deeper lots and
loading setbacks. This is a visual grammar, not proof of industrial semantics;
source building dimensions and roles must remain unchanged.
HYBRID subdivides one physical district into connected planning regions with
different grammars, not just different profiles in neighboring districts.
Region borders reserve shared streets and preserve original directory ownership.
Record region polygons/profile and each parcel's region profile for inspection.

All physical corridors precede frontage candidates. Use bounded spatial checks
for full-width street clearance and parcel overlap. Entire building meshes and
door points share the frontage frame. Exact logical trips use these corridors,
not a separate decorative path. Hints require the same policy and retained
region geometry; incompatible policy changes explicitly replan. Reuse source
IDs, canonical UCG/City, existing browser rendering and CPU projection.

Add generator/profile/policy values to the experimental World schema without
invalidating old documents. Explicit modes may need more circulation land;
record capacity repairs and area, never hide missing entities behind fallback.
Compare real four-repository outputs, maintained small and unknown fixtures,
repeat bytes, controlled added-file hints, collision/access/edge conservation
and actual browser/CPU captures. Keep rendering/data growth measured. This does
not complete terrain, hydrology, semantic LOD or arbitrary concave geometry.
