# ADR-028 — Evidence-backed neighborhoods inside the experimental world

Status: maintainer requested incorporation of the hierarchical zoning proposal,
2026-10-19. Initial opt-in, flat/convex vertical slice only.

## Decisions before implementation

Keep UCG/City and the default World generator byte-compatible. Add an explicit
`--zoning semantic` option; the default is `none`. Persist a separately versioned
`planning/0.1-experimental` projection as `planning.json`, backed by the same
optional planning object in World. Additive fields/version enums in the existing
experimental World schema must not invalidate previous documents.

Use the existing bounded convex half-plane kernel, no new dependency or native
rewrite. Child cells are clipped additively weighted Euclidean power cells,
with fixed initial sites and bounded area optimization. Record convergence and
area error; fall back to shared-cut capacity bisection when infeasible. Confirm
actual frontage capacity separately: target area alone is not proof of capacity.
Reserve streets before parcels, preserve every source building and relationship,
and report repair/fallback explicitly. No disconnected/concave/holed land yet.

For the first candidate policy, accept only DIRECT/RESOLVED source roles with
existing evidence. Keep all claims per specialized member; ambiguous or missing
roles are neutral. Minimum specialized group: 12 files; district threshold: 24.
At most seven categories per district and one internal zoning level. These are
versioned prototype policy constants, not measured universal optima. A single
meaningful cluster skips tessellation. Directory/service parent boundaries are
hard ownership constraints. No centrality-as-orchestration or name-as-technology.

IDs derive from parent stable identity and category/version. Compatible previous
zone sets may keep polygons, profiles and parcel slots while capacity fits.
Changed sets or exhausted capacity explicitly replan; arbitrary renames and all
cold small edits are not promised stable. Original directory IDs remain attached
to every parcel. Future sub-clusters require persistent ownership keys.

Terrain suitability will precede clipped zoning when terrain is implemented;
this version explicitly records flat terrain with no water masks. Do not invent
bridge/tunnel success. Browser chunking, aggregate expansion and full block
subdivision remain separate decisions, not implicit schema promises here.

## Consumers and gates

Generator, schemas, independent validator, packaging/manifest, browser inspector,
CPU preview and tests consume the same derived zones. No browser-side reclustering.
Physical borders are planning constructs, never source modules or dependencies.
Structural access streets and source-backed trips remain visually disclosed.
Compare four actual repositories, fresh fixtures, repeat output, small-edit hints,
claim tampering, geometry failures and bounded solver fallback. Record limits,
area growth, elapsed stages and actual rendered findings in QUALITY_LOG.

Implementation refinement: before growing a parent, use one bounded target
rebalance from observed frontage capacity, then shared-cut retry. Store final
`areaTarget` beside analytic `areaDemand`; do not conflate them. Compare four
GRID axis/phase fits inside each new zone and leave0.01-unit lot clearance.
These changes are opt-in only. Retain neutral GENERAL_MIXED rather than forcing
all seven illustrative proposal categories; SERVICE_QUARTER avoids inventing
an orchestration/CBD conclusion from a service annotation alone.
