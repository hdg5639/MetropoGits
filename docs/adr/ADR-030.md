# ADR-030 — Source-core neighborhoods and pattern-independent road-cut blocks

Status: implementation of the maintainer's2026-10-19 correction and the already
requested hierarchical design sections8/9. Additive opt-in; retain older modes.

## Decision

Introduce `--zoning neighborhoods`, a new experimental physical generation
policy, not a replacement of UCG/City or a change to existing mode meanings.
Retain source-owned service boundaries and semantic core files from tested
DIRECT/RESOLVED role evidence. Attach existing unclassified supporting files
only via explicit local dependency edges, record those IDs, cap attachment
relative to core size, and retain mixed/unknown remainder. Do not reclassify
supporting files or claim a pure-purpose neighborhood.

Allocate real neighborhood land before streets/addresses. Precompute bounded
convex road-cut development blocks and a shared collector/access backbone,
independent of local grammar selection and subsequent entity-to-lot assignment.
Re-use existing planning grammars within those blocks, not as an entire-service
stencil. Use exact shared cuts/ports; avoid paving every semantic Voronoi border.
Any block edge that is a neighborhood/outer boundary rather than a physical
street must be disclosed; this first bounded slice is not a claim that every
block is a fully road-enclosed face of an arbitrary planar graph.

Keep neighborhood core membership distinct from original per-file roles and
supporting-member provenance. Preserve all original files and exact route edge
IDs. Geometry never establishes a communication claim. Scope remains flat and
convex; no new dependency, native rewrite, target execution, terrain or hydrology.

## Compatibility and gates

Use `flat-neighborhoods/0.1`, `neighborhoods/0.1` metadata in the additive
experimental World; version the derived planning projection separately.
Existing hard/soft World documents and City/UCG consumers remain valid.
Explicitly diagnose incompatible hint replans; compatible growth retains old
neighborhood/block anchors and existing slots where capacity permits.

Validate source cores/attachments independently, real polygon containment,
block area and boundary types, main-road invariance under local pattern
ablation, complete source/edge conservation, full-width clearance, all-door
access, repeat bytes and nearby-revision stability. Inspect four real
repositories plus a fresh maintained fixture in WebGL/Canvas/CPU. Record limits
and failures; do not claim acceptance of an entire procedural-world design.

The accumulated requirements and deferred work are in
[WORLD_EXECUTION_LEDGER](../WORLD_EXECUTION_LEDGER.md); feedback does not erase
previous requirements. Materials are explicitly deferred, not cancelled.
