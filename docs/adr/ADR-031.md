# ADR-031 — Inherited district street patterns, physical semantic subdivisions

Status: maintainer-requested correction, 2026-10-19. Additive experiment;
retain ADR-030's existing block-local mode and all canonical UCG/City contracts.

## Problem and decision

The neighborhood output retains evidence-backed cores, but restarting grammars
inside small development blocks and falling back to GRID destroys their larger
character. The maintainer requests a recognizable large pattern as the base,
with natural internal neighborhood subdivision, not isolated pattern fragments.

Add `--pattern-scale district` to `--zoning neighborhoods` (default remains
`block`). Choose the existing GRID/ORGANIC/RADIAL/INDUSTRIAL/HYBRID grammar at
the source-owned principal district scale. Reserve its real continuous street
field before assigning any source file. Shared origins, phases, radial hubs,
curves and hybrid subregions survive semantic boundaries. Do not create a new
hub/axis at each neighborhood, silently substitute GRID, or promise every
grammar appears in every repository. Provide an explicit five-grammar atlas.

Allocate physical evidence-backed neighborhoods inside that street field.
Capacity is measured from whole, clearance-validated frontage sites inherited
from the parent, not independently restarted local planners. Repair bounded
land allocations when necessary; fail explicitly instead of dropping files or
fabricating facilities. Neighborhood boundaries are administrative subdivisions,
not automatically pavement. Initially each neighborhood is one development
sector; disclose this instead of calling it an enclosed road block. Road-face
extraction and finer local infill remain later work. Buildings and entrances
inherit the actual street tangent; exact source roles and trips remain intact.

This refines W-05/06: a **macro street pattern** may influence main roads,
while downstream neighborhood labels/local address assignment must not restart
that pattern. It does not restore the rejected soft experiment: all semantic
core files must physically remain inside their own neighborhoods, with original
supporting-edge provenance. No arbitrary cross-service shuffling.

## Compatibility and gates

Explicit `patternScale: district`, `flat-neighborhood-patterns/0.1`, additive
`district-patterns/0.1` metadata and `planning/0.4-experimental` distinguish the
experiment. Preserve old block-scale bytes/meaning and reject incompatible
hints with a disclosed cold rebuild. No UCG/City schema or source ID changes.

Independently reconstruct the reserved parent field, verify full-width physical
coverage and parcel inheritance, core/support ownership, source dimensions,
all entrance access and exact trips. Check same-input bytes and hinted edits.
Inspect CPU/WebGL/Canvas output on GJ/OJ/PocketBase/SQLiteBrowser and a fresh
maintained fixture; measure land/timing and report failures honestly. Compare
all five requested profiles without fallback. Do not hide structural defects
with colors, new ornaments, or arbitrary road-angle jitter.

The full accumulated requirements remain in WORLD_EXECUTION_LEDGER; materials,
broader role mixing, LOD, density and terrain are not cancelled by this request.
