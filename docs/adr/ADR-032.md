# ADR-032 — Relationship-mixed neighborhoods and adaptive pattern hierarchy

Status: maintainer-requested correction, 2026-10-19. Retain prior experiments
for comparison, not as accepted visual baselines. Original City/UCG unchanged.

## Reject both extremes together

ADR-030 restarts small patterns and often collapses to GRID. ADR-031 reserves
the entire parent stencil, so every neighborhood repeats that same morphology.
Both still use role-exclusive cores and admit only unknown helpers. The address
optimizer cannot put related verified Service/Repository files together across
those boundaries. Role-colored piles and shorter within-pile distances are not
the requested functional mixing. Preserving exact edges is necessary, but does
not by itself make the planning relationship-aware.

## Bounded opt-in correction

Add `--pattern-scale adaptive` with neighborhoods. Inside each immutable
source-owned principal district, group files using actual DIRECT/RESOLVED
file/symbol dependencies (not CONTAINS/DECLARES), bounded source-anchored region
growth and disclosed structural packing for disconnected files. Roles describe
each mixed group's actual occupants; they are not exclusive bins. Every verified
role remains attached to its own file, all original evidence is preserved, and
group membership/internal edge IDs are independently reconstructed. Unsupported
frameworks receive no invented facility semantics. These are derived planning
neighborhoods, not discovered runtime services or authoritative code modules.

Keep only a sparse, recognizable arterial skeleton from the parent pattern.
Within physical neighborhoods, retain parent frontage where appropriate and
adapt the local grammar to actual occupants and access geometry elsewhere.
Do not overlay a full old stencil under the replacement. Reserve shared main
corridors before local lots, maintain clearance, join actual boundary access
ports, and preserve exact source-target trips through real intersections.
Administrative borders are not automatically roads or fully enclosed blocks.

Use explicit adaptive generator/zoning/planning versions and separate hint
compatibility. Old modes keep their meanings/bytes. Cold planning groups may
change on meaningful graph edits; report replans, test hinted nearby edits and
never claim universal geography stability from one fixture.

## Acceptance gates

- Compare both prior extremes and the correction with identical graph/seed.
- Measure cross-role dependency pairs physically co-located, not a random color
  ratio. Inspect concrete Service/Repository/Controller examples and edge IDs.
- Demonstrate retained AND adapted morphology in the same real principal
  district, with a continuous reserved skeleton and real access connections.
- Check complete files/edges, role/evidence fidelity, parcel/full-width road
  clearance, entrances, determinism, hints, bounded work and legacy compatibility.
- Inspect actual GJ/OJ/unknown corpus CPU/WebGL/Canvas, not just tests/JSON.

If these two goals cannot be achieved together, report the failed experiment;
do not promote a halfway implementation or forget either requirement again.

## Seam correction — 2026-10-19

The maintainer reports two terrain/pattern layers appearing superimposed in
adaptive-neighborhoods-r3. Inspect geometry as well as renders: negligible
quantized ground slivers are distinct from a second parent frontage lattice
crossing the adapted street field. The first correction reserves parent
collectors/spokes/spines as shared infrastructure, not every third frontage
row/court or fourth orbit when true connecting arteries already exist. The
inherited neighborhood keeps its full original pattern; adapted neighborhoods
keep their own local grammars and source-based mixed memberships. Existing
port/perimeter connections still join streets; a shared intersection invents
no source edge. The no-artery fallback remains available for bounded sparse land.

Version this opt-in generator as flat-adaptive-neighborhoods/0.2 and its pattern
policy as adaptive-patterns/0.2. Keep address seeds/source identities unchanged;
reject older hints with an explicit cold-rebuild diagnostic. Validate legacy
0.1 exports against their old reservation policy. Add only compatible version
enums to experimental schemas; City/UCG and planning fields remain unchanged.
Reject invalid quantized child land before placement and use the existing
bounded small-demand repair; do not loosen clearance/containment tolerances.

Compare the same four source snapshots/seeds and actual matched renderer views.
Require unchanged neighborhood membership/roles, retained and adapted patterns,
exact edge coverage, complete entrance access, legacy validation and repeated
bytes. Report any geometry relocation/density regression rather than implying
that unchanged seeds guarantee old coordinates after a generator revision.
