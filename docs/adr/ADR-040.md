# ADR-040 — Sparse permeability before frontage occupation

Status: user-authorized connectivity correction, 2026-10-19; implementation
planned as opt-in `--street-policy porous`. Existing policies remain unchanged.

## Problem and outcome

The gap-only alley pass requires six nearly collinear buildings, a gap9–30,
similar rotation and a target within44 units. Curved orbital rows, wide vacant
blocks and tightly sampled frontage are frequently excluded. Parallel streets
then connect only at an outer collector, producing excessive internal detours.

After terrain adaptation but BEFORE source-to-lot assignment, compare nearby
physical streets across their interiors, curves and selected dead ends. Reserve
only a few narrow, genuinely two-ended links where existing graph detour is
large. Candidate points follow street geometry; no global transverse stencil.
Prefer clear passages, permit removal of a few UNASSIGNED candidate lots only
when neighborhood capacity remains sufficient. Never omit a source building,
cut a whole occupied parcel, cross protected water/mountains or invent edges.

Keep wide spatial separation and strict per-parent/global work bounds. Reject
short redundant links, dense cross-grids and long speculative roads. Preserve
parent morphology, mixed source neighborhoods, fronts and terrain-first order.
If no safe useful passage fits, keep the certified original plan and disclose it.

## Contracts and consumers

Add an optional street-policy enum and explicit permeability/0.1 plan metadata
in experimental World. Natural generators retain their terrain versions; their
pinned policy distinguishes the new planning configuration. New flat planning
uses flat-adaptive-neighborhoods/0.6. Old policy outputs/IDs keep their meaning.
Geography hints must not silently cross the new planning-policy boundary.

Generator and independent block reconstruction must run the same deterministic
reservation rules. New links become real atomized pavement/junctions; reroute
exact original source trips, keeping selection and Synthetic on their own paths.
Structural links alone do not imply runtime communication or invented traffic.

## Verification and restraint

Test curved rings, straight dense rows, vacant wide blocks, existing nearby
links, terrain barriers, capacity limits, deterministic input order and resource
exhaustion. Compare pinned GJ/OJ/PocketBase/SQLite plus maintained sparse input in
actual CPU/WebGL/Canvas. Measure link counts, reclaimed candidate capacity,
unchanged source/roles, area/position changes and real detour reductions.
Passing geometry tests is not visual acceptance. Keep materials/LOD/terrain
backlog; do not turn this task into a wholesale city rewrite.
