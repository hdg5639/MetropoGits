# ADR-044 — Architectural wall tones with evidence-linked roof accents

2026-10-19. Implements the already requested W-15 presentation separation.

## Context and scope

The maintained worlds now pass complete frontage, geometry, campus-access,
source conservation and repeatability checks (ADR-041–043). Campus variants and
cross-boundary transitions are not all complete. Another small campus geometry
tweak would affect only a few plots, while category-coloured walls still dominate
every city. Take a bounded presentation slice, not a new lighting/material engine.

## Decision

- Opt-in `--building-style architectural` affects World **packaging only**.
  Default `semantic` retains the existing output. World, City, UCG, planning,
  source dimensions, footprints, parts, ownership, streets and trips stay exact.
- A pinned `building-materials/0.1` viewer policy selects restrained wall/roof
  tones by stable entity identity, independently of role, size or graph degree.
  These colours are procedural styling, not observed construction materials.
- Existing highest roof faces carry the existing archetype colour as an accent.
  Generic files remain generic; no framework or capability is inferred.
- CPU SVG, WebGL and Canvas use the same palette/selection rule. All LOD masses
  use the policy, including persistent role compounds. No extra buildings,
  geometry surfaces, network claims, textures, services or runtime dependencies.
- A keyboard-accessible Role colours button restores full category tint. Active
  filters and selected buildings also use strong category tint. Evidence and
  exact aggregate member/source inspection remain available in either view.
- Recolouring invalidates the existing static cache once per interaction, never
  per Synthetic frame. No new per-frame routing, triangulation or material work.

## Compatibility and validation

No public UCG/City/World schema change. The versioned policy is optional private
viewer presentation data and explicitly recorded in the package manifest.
Equivalent entity IDs retain their colour when unrelated files are added.

Test Python/JavaScript palette parity including non-ASCII IDs, role independence,
highest-roof accents, unknown fallback, default byte compatibility and unchanged
canonical artifacts. Compare real same-camera Overview/District/Detail captures
on GJ, OJ, PocketBase and unsupported SQLiteBrowser, plus the small Hanul world
and maintained source fixture. Check Canvas, CPU preview, role toggle, filters,
source/edge drill-down and Synthetic static-build reuse. Do not infer GPU FPS
or claim finished architecture, lighting or the remaining planning milestone.
