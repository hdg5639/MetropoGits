# ADR-046 — Purpose-aware campus walking tail cleanup

2026-10-19. Follow-up to the user-authorized whole-neighborhood campus correction
(ADR-045). Keep that planning unit; do not return to eight-file garden pockets.

## Observed defect and bounded correction

The frozen `campus-neighborhood-r2` output contains non-access walking leaves:
GJ53 (737.5 ground units), OJ33 (278.1), PocketBase19 (179.2). Some GJ leaves
exceed60 units. These are initial candidates, not proof that all are purposeless.
Raw frontage wings were protected as main-road reservations even beyond the last
occupied address. More curves or trees would hide, not correct, the excess.

Apply offline `campus-circulation/0.1` after atomic intersections, source access,
exact trip routing and existing road repairs. Delete only walking graph leaves
with no occupied frontage, doorway, shared court loop, promenade, exterior gate,
protected non-campus corridor, bridge/tunnel or source trip. Repeatedly peel a
tail until reaching real access or a retained junction. Dependency demand is NOT
the definition of structural usefulness: generic/unreferenced files and public
circulation remain accessible even with no source edges.

This is deletion-only. Do not reroute, relocate buildings, expand land, move
terrain, replace the parent pattern, invent roles/relations, or resample meshes
per frame. Leaf removal cannot increase remaining pair travel distances. Work
limits retain the complete original certified graph, never a partial repair.

## Compatibility and independent verification

No UCG, City, World schema, source/parcel identity, dimensions, role, ownership or
campus-plan/0.3 layout contract changes. Existing `walkways`/`mainRoads` continue
to describe pre-assignment planning reservations. Built and rendered pavement
is the authoritative `streets` graph; the unused part of a reservation need not
be built. Courts, membership, activity groups, addresses and planning bytes stay
identical. Do not render a raw reservation as an additional road.

New neighborhood outputs record the optional policy version and exact omitted
atomic geometry/physical IDs/length in diagnostics. Prior outputs without this record still
require complete reserved pavement and validate unchanged; quad/varied modes
do not run this cleanup. Reproduction of the older untrimmed output uses its
pinned revision (`d7393de`), not an assumption that a bug fix preserves all built
street bytes under the same experimental planning schema.

The validator must not trust an omission list. Restore actual pavement plus
the exact omitted atomic pieces, check canonical geometry IDs, rerun the purpose
test against independently reconstructed reservations, and accept only those
verified omitted pieces for reserved-centerline coverage. Re-atomizing the raw
planning reservations is not equivalent: prior seam/junction repairs and
quantization have already changed the built graph's intersection segmentation.
Normal
building/port/source-path/terrain/overlap checks remain mandatory. Forged omission
IDs or deletion of a useful court/access corridor must fail validation.

## Acceptance and limits

Compare actual before/after WebGL and CPU previews on GJ/OJ/PocketBase and an
unsupported-language negative case. Run a maintained source fixture from scan
through package, repeat bytes, all-member navigation, Synthetic cache/path tests,
schema and old-mode regressions. All parcel frames and exact routing records
must remain identical. Report measured pedestrian reduction, not total-city
improvement percentages. This does not finish organic campus morphology,
riverside transitions, service/emergency travel modes or landmark architecture.
