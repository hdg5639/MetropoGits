# ADR-064 — Source-first urban character and relative spatial demand

2026-10-22. Accepted implementation slice of the maintainer's mandatory urban
redesign; not acceptance of the five master planners or new physical geography.

- Add a standalone, layout-independent CharacterEngine. It can run before any
  World exists, with explicit repository/directory/zone source membership.
- Count verified unique local file pairs, boundary coupling, external usage
  separately from declared dependencies, normalized degree centralization,
  weak components, module distribution, and evidenced role/capability usage.
  Weak components are not semantic community detection. Unknown remains unknown.
- Separate reconstructable `facts` from aesthetic `planning` and relative
  `spatialDemand`. Record source membership, original edge IDs and evidence.
  Fixed deterministic formulas are pinned to urban-character/0.1 and
  spatial-demand/0.1. They do not diagnose code quality or runtime traffic.
- Catalog packages add checksum-covered `urban-character.json`; no changes to
  UCG, City, World, existing Planning or source IDs. Existing modes stay intact.
  Current World scopes are analyzed for an inspectable migration baseline;
  they are NOT silently replanned after buildings have been placed.
- Demand uses relative program-equivalent units, NOT promised square metres or
  already admitted parcels. Terrain-aware land allocation/master planning is
  a separate consumer. Typology preferences do not constitute constructed CBDs.
- Bound files/edges to10,000/200,000, index incident edges once; no all-pairs
  centrality or stochastic community solver. Nothing executes target sources.

This dependency is delivered before the new master planners. Do not return to
per-file fan-in -> HQ/tower, or call profiles alone the completed redesign.
