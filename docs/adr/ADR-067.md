# ADR-067 — Demand-first physical capacity replanning

Status: accepted by the maintainer's explicit capacity-replanning directive,
2026-10-22. Supersedes ADR-066's immutable-geography restriction **only for the
new opt-in capacity planner**. UCG and City schemas/identities are unchanged.

## Decision

Compute source-evidenced architectural programs before land allocation. Feed
their physical dimensions and circulation/reserve demand into district and
neighborhood allocation. Reserve variable parcels before buildings and route
dependencies only after physical roads, doors and protected terrain are final.
An undersized previous geography is a hint, not an invariant: deterministic
local demand repair may expand districts and rebuild affected infrastructure.

The optional `capacityPlan` extension on experimental `world/0.1` explicitly
versions this producer/consumer behavior as `capacity-replan/0.1`. Original
City dimensions remain in the unchanged source artifact; physical dimensions
are derived programs, not new code facts. Validators reconstruct the program
and check physical dimensions against it. Old Worlds retain their strict City
dimension checks. No old validator is weakened to accept arbitrary geometry.

Every source must have exactly one allocated physical address (or a certified
address inside a compound). Program area cannot be silently reduced. Exhausted
bounded repair is a hard generation error, not a successful deferred export.
Roads, access, surface grades and water/mountain crossings are recomputed by the
existing physical infrastructure pipeline after placement.

## Acceptance

GJ-Cloud, GamjaOJ, PocketBase and SQLiteBrowser: zero unresolved allocations,
exact source/evidence/edge conservation, parcel/building/road exclusion,
connected doors and required routes, deterministic regeneration. Report
required versus allocated land, actual footprint/height distributions, actual
rendered morphology similarity, timing and browser measurements; inspect
matched-camera grayscale overview, district and street renders.

The previous urban-land experiment and older generation modes remain readable.
No claim of completion follows merely from program labels or larger envelopes.

## Whole architectural sites, capacity-replan/0.2

Physical requests now include bounded source-affinity cohorts before allocating
land. Cohorts use existing static edges and shared local targets within the
functional neighborhood; shared land never asserts a new peer dependency.
Private planning units reserve up to four actual source envelopes plus exterior
shared access. Each real file retains its own full dimensions, ID, role, door
and graph paths. Private unit IDs never enter the source entity census.

Site dimensions, rather than old eight-unit glyphs, set local street spacing.
The capacity mode regenerates local service aisles on the neighborhood frontage
axis; inherited district arterials, functional boundaries and protected terrain
remain constraints. This deliberately replaces small-plot local road geometry;
it is not a claim to preserve every former organic/radial local stencil.
Insufficient neighborhoods receive stronger local demand repair while already
successful neighbors do not gain artificial repair weight. Parent repair still
expands/regenerates geography when needed. Site relief is checked per actual
building foundation and shared walking profile, not as if an entire multi-body
campus had to be one flat slab. Existing relief/grade limits are unchanged.

Certified complexes are cleared against other sources, public streets, courts,
terrain and prior complexes. Constituents keep logical interior addresses;
their access graph remains intact, but both renderers clip public access
pavement out of the complex's ground-floor solids. This is an explicit
indoor-address presentation, not deletion of a dependency or disconnected road.

`urban-architecture/0.2` and physical campus massing use compositional variants
of actual volumes, roofs and voids. Complex heights follow their physical form
and site span, not the former 30/36-unit aggregate glyph ceiling. There is no
global source-count-to-height rule or arbitrary universal height clamp.
Legacy capacity-replan/0.1 Worlds remain independently reconstructable.

## Saved-artifact compatibility

Capacity-mode street hierarchy uses `street-plan/0.2`: port/component identities
hash canonical numeric coordinates, not Python's integer-versus-float display.
This fixes validation after canonical JSON reload without changing source IDs.
Final linear door ramps explicitly mark `linearRamp: true`; the same two-endpoint
ramp geometry is reconstructed by the height validator. Old-mode street-plan
and access-profile encodings remain unchanged. The procedural CLI normalizes
strictly decoded previous hints to native geometry numbers, preserving strict
duplicate-key and nonfinite-input rejection.
